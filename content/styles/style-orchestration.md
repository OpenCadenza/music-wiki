# Style and orchestration cards

## id: `style.evidence-boundary`

- type: procedure
- facets: style, composer, imitation, evidence, uncertainty
- sources: project-workflow
- confidence: established
- scope: Requests to compose "in the style of" a composer or period
- signals: Each style claim names a work, passage, parameter, and transferable
  mechanism; the score contains a corresponding observable feature.
- counterexample: "Impressionist" or "Ravel-like" is not an executable
  specification.
- limits: Scholarship can disagree and a single work may not represent a whole
  career.

Use a style scope such as period, instrumentation, work, and task stage. Keep
copying, allusion, and general influence distinct.

## id: `style.ravel-timbre-form`

- type: analysis
- facets: Ravel, timbre, orchestration, form, auditory stream, illusion
- sources: ravel-sound
- confidence: interpretive
- scope: Late orchestral works discussed by Jennifer P. Beavers
- signals: Changes of instrumental grouping, register, attack, and timbral fusion
  articulate a boundary, transformation, or developmental space.
- counterexample: Instrumental color is not merely decorative if the source
  demonstrates its structural role.
- limits: The evidence does not define a universal rule for all Ravel works or
  for string quartet writing.

When transferring the idea, define the audible stream and formal transition.
Do not imitate an example's exact orchestration without checking the target
ensemble.

## id: `style.ravel-harmonic-language`

- type: analysis
- facets: Ravel, harmony, chamber music, tonality, style
- sources: ravel-cambridge-harmony
- confidence: interpretive
- scope: Chamber-music analysis summarized at abstract level
- signals: Claims connect chord structure and voice leading to a dated work,
  phrase, and formal purpose.
- counterexample: A composer label should not be treated as a preset collection
  of chords.
- limits: The abstract and bibliography are discovery evidence; the full
  chapter or actual score is needed for detailed imitation.

Create a source gap when the specific harmonic mechanism is not supported. Use
corpus evidence only after its provenance, conversion, and rights are known.

## id: `style.composer-model`

- type: procedure
- facets: style, composer, period, model, transfer
- sources: project-workflow
- confidence: provisional
- scope: Building a style brief from analysis sources
- signals: The brief separates historical period, ensemble, formal model,
  harmonic vocabulary, rhythmic behavior, texture, and timbre; each clause has a
  source or score anchor.
- counterexample: Weighted adjectives and composer names are not a style model.
- limits: No finite set of descriptors guarantees likeness or quality.

Build the brief as testable propositions. Mark each one as mandatory,
preferred, or optional.

## id: `orchestration.register-and-role`

- type: procedure
- facets: orchestration, register, range, role, playability
- sources: philharmonia-instruments, project-workflow
- confidence: established
- scope: Instrumental and vocal scoring
- signals: Written pitch, sounding pitch, practical range, transposition, and
  simultaneous span are verified for the actual performers.
- counterexample: A parser accepting an out-of-range pitch does not make the part
  practical.
- limits: Professional and student ranges differ; extended techniques require
  separate evidence.

Give each instrument a local role. Check register crowding and hand feasibility
from grouped sounding events.

## id: `orchestration.texture-and-balance`

- type: procedure
- facets: orchestration, texture, balance, doubling, density
- sources: ravel-sound
- confidence: provisional
- scope: Multi-instrument scoring
- signals: The primary line, supporting harmony, bass, and color are distributed
  across identifiable registers and attacks without ambiguous doubling.
- counterexample: Assigning more players to a line does not automatically create
  orchestral balance.
- limits: Loudness, instrument timbre, room, and performance dynamics require
  audition or score-informed judgment.

Review each phrase as roles and trust. Where two instruments merge, state whether
the result should be one blended stream or two audible lines.
