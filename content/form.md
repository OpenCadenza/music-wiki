# 曲式与连贯
蓝图记录乐章/段落功能、比例、调性或音高集合、主题来源、织体、高潮及衔接。段落按音乐意义分，不默认每八小节断开。
奏鸣曲呈示区分主题与调性关系；展开加工既有动机并组织张力；再现处理调性解决，允许符合任务的变形。不能用三个标题替代实际结构。变奏需与主题有证据联系而兼具性格差异。
写作单元同时写所有相关声部。段落接缝检查延音、低音、转调、终止强度和张力方向；避免每段强收束。多乐章主题跨章引用保持原谱事实。完成后回读全章/全曲，确认规模、声部、材料与指定技法，不以最后一个段落写完代替全曲复核。

## 分层读谱与规划

| 层级 | 写作前的最小决定 | 回读时找的证据 |
| --- | --- | --- |
| 乐句 | 材料重复、继续或对比；终止目标 | 基本乐思与后续单位的关系；实际和声到达 |
| 呈示 | 主调、过渡目标、副部及其闭合 | 主题与调性功能，不仅是旋律差异 |
| 展开 | 加工哪段材料，怎样制造不稳定 | 派生关系、模进单位、调性与和声节奏 |
| 再现 | 哪些段落对应，哪里需要重写 | 与呈示逐段对照，调性矛盾是否得到处理 |
| 多乐章 | 对比、联系、重量和结束姿态 | 实际引用音符、前后乐章衔接与总体比例 |

最后一行是项目规划方法，不是某一种曲式学说的定律。先用 [曲式卡](forms/phrase-form.md) 确定模型，遇到例外保留实际证据，不强行“纠正”历史作品。

来源定位：[OMT thematic modules](https://openmusictheory.github.io/sonataThematicModules.html) 的 P / TR / S / C；[development](https://openmusictheory.github.io/sonataDevelopment.html) 的 Tonal / Thematic organization、Four modules；[recapitulation](https://openmusictheory.github.io/sonataRecap.html) 的 Recomposition / Crux。这些属于特定奏鸣曲分析框架，不能机械外推到全部时期。

变奏可改变节拍、织体、调式或材料角色；先声明哪些关系维持，哪些改变，再查实际谱。依据 [Rubin, Theme and Variations](https://open.lib.umn.edu/musiccomposition/chapter/composing-a-theme-and-variations/) 各变奏及 Ending the Variations；不要求每组变奏都按该教材的顺序。
