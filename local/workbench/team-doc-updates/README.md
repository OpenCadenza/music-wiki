# Music Wiki 知识生产：阅读、理解与著述

本页说明全局目标、目录架构和生产方式。写作原则见[writing-rules](writing-rules.md)，资料见[sources](sources.md)，谱例工程见[score-pipeline](score-pipeline.md)。实际状态分别记在[handover](handover.md)与[progress](progress.md)。

## 我们写什么

知识库面向学习音乐的人与音乐创作 Agent，内容涵盖理论、技法、作曲家风格、作品特点、体裁、编制与必要背景。创作帮助是重要目标，文章也应帮助读者理解音乐，不能缩成每篇必须教一个改音符的动作。

作者先实际阅读教材、研究、作品与作曲家资料、原谱等材料，从中发现有价值的问题，再围绕问题补充阅读、形成理解并写文章。谱例是真实作品的例证，不能替代其他知识输入。

允许有根据的独立分析、比较和新归纳。既不能用模型记忆现场编写知识，也不要求每句话在文献中找到同一句结论。

## 知识库架构

采用问题轴、语境轴与工具轴：

~~~text
content/
├── index.md                      # 定位与材料／结构／音响三个尺度
├── techniques/                   # 问题轴：可跨语境推广
│   ├── index.md
│   ├── material/                 # 动机、乐句、主题、细胞
│   ├── structure/                # 曲式、段落、调性布局、终止、比例
│   ├── harmony/                  # 调性关系、和声语汇、半音体系
│   ├── counterpoint/             # 模仿、卡农、赋格、声部进行
│   ├── rhythm/                   # 节拍、速度、节奏型、弹性速度
│   └── sound/                    # 音区、织体、厚度、力度、配器
├── composers/                    # 语境轴：某人某体裁的具体做法
│   ├── index.md
│   └── <作曲家>/
│       ├── index.md              # 总体特点，写音乐实质
│       └── <体裁>/
│           ├── index.md          # 体裁的问题地图
│           └── <选题>.md
├── ensembles/                    # 语境轴：编制的惯例与限制
│   └── <编制>/
├── styles/                       # 语境轴：非作曲家体系的风格
│   └── <风格>/
└── notation/                     # 工具轴：记谱与实现
    └── <主题>.md
~~~

学者根据选题自主决定文章位置，可以新建子目录。技法六维保留，体裁与曲式的通用问题纳入 structure，具体语境在作曲家／编制等入口展开，不新增 forms 或 genres 顶层轴。

一篇文章只有一个主要位置，其他语境用链接关联。相关问题可以互相链接；同一段谱例只维护一份。没有内容的目录不预建空页。

目录页也写音乐实质：作曲家特点、体裁的问题地图、技法之间的关系。它们不负责列出文件清单、检索词或证据登记。

## 两个阶段

**预备轮**由资料初步整理角色把已有原件变成可发现、可阅读的资料库，建立目录、来源关系和可读范围。PDF 等非文本文档采用当前已选定的转换工具；原件保留，加工发生在副本中。

**正式轮**由音乐学者自由选题和写作。资料初整角色退出；资料收集助手负责查找、保存原件，并亲自完成转换、清理和入库，再交给学者。正式轮新增资料和预备轮资料同等可用，其他学者也可由新资料发现选题。

自动化协作主要使用 Codex 原生子代理消息交接请求和资料。公共看板展示每位学者的在研选题、资料范围、进度和关联，帮助同行了解全局，不作为助手抢单队列。

## 文章怎样完成

学者决定标题、结构和篇幅，不按固定模板、作品数或字数填空。主要解释要有实际阅读和音乐观察支撑，正文语言清楚、有观点，也讲清为什么。

缺可嵌入代码可以保留真实谱例定位；缺中心知识就继续研究，不能用“谱例待补”掩盖未做的阅读。

按需安排编辑复读，聚焦主要理解、推理和可读性。工程只检查可用性和既有格式，不把编译通过当成知识正确，也不进行全面逐句逐音审计。

每篇完成后，学者把对应看板记录归档，主控串行提交本地文档仓库全部非忽略改动，形成过程快照。原始资料、加工资料与大型产物继续忽略。正式正文的外层提交与发布按[页面部署](../music-wiki-页面部署/README.md)流程另行处理。

## 三层资产

- 原始资料库：保存取得时的文献、谱源、来源与失败记录。
- 阅读资料库：保存可读文本、图像、标注和按需加工的谱源，统一提供发现入口。
- 正式知识库：`content/` 中的音乐文章与实质导论。

来源卡、阅读笔记、许可、下载记录和协作状态在正文之外保存。公开来源与许可由 NOTICE 统一登记，详细生产记录留本地。旧 Agent 生成文章和自编模型不能混作可信文献输入。

个人偏好、单个作曲家详细交接和本机运行路径由各负责人保存在本地。团队文档写全局方法与可共同使用的接口，实际进度不写成永久规则。
