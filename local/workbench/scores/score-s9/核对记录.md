## 4. 编码说明

1. 无 `\header`；`\version "2.26.0"` 恰好 1 次；`\language "english"` 1 次；自包含，无 `\include`。
2. 4 个 `\new Staff`，各自 `\set Staff.midiInstrument` + 紧邻一行 `% GM`：violin 40、cello 42、piano RH 0、piano LH 0（钢琴用 `PianoStaff` 包两个 Staff）。MIDI 实测 program 依次为 40 / 42 / 0 / 0。
3. `#(set-global-staff-size 18)`：默认字号下 21 小节 4 行谱要排 2 页（第 2 页只剩 1 个系统）；18 号正好 1 页，19 号又会溢出到 2 页。仓库内已有 3 处同类用法（`content/.../cadential-evasion-and-temporal-expansion.md` 等）。
4. **速度：谱面只留文字，数值只进 MIDI**。源没有 `<metronome>`，所以不能印「♩ = 40」；但 MIDI 需要 40，故写成
   ```
   \tempo "Andante con moto"
   \set Score.tempoWholesPerMinute = 10
   ```
   10 个全音符/分钟 = 四分音符 40/分钟。`\tempo` 只给文字（不带数值时不印节拍机），`\set` 只改播放速度、不出字形；实测 MIDI 里恰好 1 条 tempo 元事件 = 40.00 bpm，编译 0 warning。
   （注意：2.26 里 `tempoWholesPerMinute` 要的是有理数，写成 `#(ly:make-moment 10 1)` 会报 "must be of type positive exact rational"，用 `10` 才对。另外 `\tempo "文字" 4 = N` 这种「文字+节拍机」组合标记在本机 LilyPond 上会把节拍机字形压在文字上，用最小样例复现过，与字号无关——这也是不走那条路的第二个理由。）
5. 记谱按 XML 逐音转写，**不修改音高/时值/奏法**：
   - 连音线（`slur`）跨小节照原样（如 m.17→m.18 大提琴、m.16→m.17 钢琴左手）；
   - 延音线（`tie`）照原样（m.12、m.16、m.18、m.20）；
   - 断奏/重音/tenuto 照原样；m.4 大提琴两个 16 分装饰音（XML 无 `<slash>`）排成不带斜线的装饰音；
   - XML 里的 `stem` 值（OMR 判定）未强行套用，让 LilyPond 自动判定符干方向；
   - A 里那些德文和弦名 `<words>` 一律不排（B/C 本来就没有）。
6. **力度记号共 13 条**（源 mm.1–21），逐条按声部与拍位写进谱面，明细见第 5 节「力度记号」小节。
   - 修正说明：初稿曾误判「mm.1–21 没有力度」，原因是我第一版检查脚本用了 `d.iter('dynamics/*')`——lxml 的 `iter()` 只接受标签名、不接受路径，于是永远返回空。改用 `d.findall('.//dynamics/*')` 后才看到这 13 条。现已把力度纳入自动比对（第 6 节）。
7. 每小节末 `|`，四个声部各 21 个。

## 7. 不确定处 / 需要人工复核的点

1. **速度 40**：见第 3 节。源无节拍机标记；独立核验按录音估 ♩≈43–49，40 只慢 8–10%，故按源保留 40，并且不把它印在谱面上（只印文字）。
2. **m.1/2/6 第四拍的「附点十六分 + 三十二分」**：这是 OMR 常常识别错的节奏型（把两个十六分或一个小符点读成 snap）。三份源一致，故照录；若手边有印谱，值得对照这一拍。
3. **三份源本质同源**：都是同一份 MuseScore 3.6.2 导出的三个副本，音符完全一致。因此这次「交叉核对」只能排除副本损坏，不能排除 OMR 错音；任何与印谱不符的地方都不是比对能发现的。
4. **m.14–16 大提琴的八度跳进**（g（G3）→ g、（G2）→ 再上回 g）看起来像 OMR 把两个声部合并到 voice 1 了（XML 里这几个音的 `stem` 方向互相矛盾）。已按单声部转写、不强制符干；若复核发现原谱是双声部，需要拆声部。
5. **m.21 小提琴进入的处理**：源文件里 m.21–22 小提琴都是同一音型（m.22 又是 g–e♭′ 八分 ×3 + snap），大提琴 m.21–22 也都是 c 八分 ×3 + snap。这看起来像是乐句收束处的两小节音型重复，但 OMR 在重复段落上出错并不罕见；截到 m.21 为止不受影响，只是提醒：**不要把 m.21 当成「小提琴从此接主题」**，它在 m.22–23 后段才真正转向（m.23 小提琴是八分音型，钢琴 m.23 才重新进入）。
6. **小提琴 20 小节全休止的排面**：按任务要求四声部全取，所以谱面上有一行几乎空白的 violin。如果成稿版面紧张，可以只保留大提琴 + 钢琴两行（删除 violin 声部与对应 `% GM 40`），但那样就看不出「小提琴全程缺席」这一论据了——建议保留。
7. **钢琴左右手各带一条力度**（m.1/15/20/21）：源里 P3、P4 是两个独立 part，各有一条 `<dynamics>`，照录后谱面上同一位置会出现上下两个 *p*/*pp*。这是「按原谱写」的结果，不是重复标注；若要合并成一条需人工决定。
8. **大提琴 m.16 连音线起点**：源从第 3 个音（G2，被延音线连住的那个十六分之后的**下一个**十六分）起，到第 5 个音 B2 止。初稿写成从第 2 个音起（早一个十六分），已按核验意见改为 `g,4~ g,16 g,16-.( a,16-. b,16-.)`，并补回第 3 个音本来有的断奏点。

## 8. 附：目录内工具脚本

- `scripts/inspect_mxl.py`：解包 5 个 `.mxl`，导出内层 MusicXML 到 `src/`，打印标题/声部/小节数。
- `scripts/diff_three.py`：三份源逐小节逐音符比对（212 小节 × 4 声部）。
- `scripts/diff_detail.py`：标签计数、articulation/slur 计数、去排版坐标后的规范化 XML 比对。
- `scripts/dump_notes.py`：把指定小节范围按声部展开成可读音符清单（`.ly` 就是据此逐音转写的）。
- `scripts/verify_ly.py`：把 `.ly` 源码与 XML 逐小节、**逐音符**比对音高组 / 断奏 / 重音 / tenuto / 连音线起止位置 / 延音线 / 力度记号 / 装饰音（第 6 节第 1 项）。
- `scripts/verify_midi.py`：解析生成的 `.mid`，与 XML 做逐小节音高比对（第 6 节第 2 项）。
- `scripts/dump_dynamics.py`：按文档顺序累积时值，输出 mm.1–30 每条 `<dynamics>` 的声部 / 小节 / onset（拍位）/ 符号（第 5 节力度表的来源）。
- `scripts/patch_lh.py`、`scripts/patch_m16.py`：本轮两处定点修补（钢琴左手 m.15/20/21 力度、大提琴 m.16 连音线起点）。
