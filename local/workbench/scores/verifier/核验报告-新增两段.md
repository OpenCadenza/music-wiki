## 1. 核验方法（可复现）

1. **核验对象取自文章本身**：用 `tmp2/extract_fences.py` 从 markdown 原样抽出两块围栏到 `tmp2/fence1.ly`、`tmp2/fence2.ly`（**核的是文章里的那 110 / 99 行**，不是生产者目录里的副本；两份内容与 `assistant-scores-d/*.ly` 的音乐部分一致）。
2. **绝对音高不靠人工推**：用 `\displayLilyMusic` 取规范文本（`tmp2/display_mozart.txt`、`tmp2/display_beethoven.txt`），再由自写解析器 `tmp2/lyparse.py` 展开 `<< \\ >>`、`\grace`、`\appoggiatura`、变时值默认继承、`\partial`，输出 `(全局起点, 时值, MIDI)`。两个文件**都没有 `\relative`**，音符全是绝对音高（`c'`=C4=60，已用 MIDI 反证），所以出现整八度漂移的结构性风险为零。
3. **源文件结构化解析（不是抽样）**：
   - MusicXML → `tmp2/src_xml.py` / `compare.xml_per_measure`：按 `<voice>` 维护独立游标、处理 `<chord/>`、`<grace/>`（零时值）、`<backup>`，得每个音的 onset/音高/时值。
   - ABC（hum2abc 输出）→ `tmp2/src_abc.py`：支持 `[V:n]`、`&` 子声部、`[和弦]`、`{}` 装饰音、`!turn!`、破节奏 `>`/`<`、各种长度写法（`2`、`/`、`//`、`/8`）、`^_=` 临时记号**含小节内延续**。
   - DCML → `n02op18-2_04.notes.tsv`（注意：其 `mc_onset` 以**全音符**为单位，须 ×4 换成四分拍；`duration_qb` 已是四分拍）；`_reviewed.mscx` 用 `tmp2/dump_mscx.py` 取 `durationType`，可判定 tie 与休止拆分。
   - kern → `quartet02-4.krn`，只用于 m.4/m.8 时值异读的交叉（该文件用 `'` 标记音高，与 DCML 对不上号，故**不用它核音高**）。
4. **比对方式**：`tmp2/compare.py` 按 `(小节, 小节内 onset, MIDI[, 时值])` 做**多重集差分**，等价于逐音全量比对，不是抽点。
5. **实编译**：`lilypond --pdf fence1.ly` / `fence2.ly`，统计 error/warning；小节长度靠每小节末的 `|`（barcheck）验证，并记录每个小节线的实际时间。
6. **MIDI 独立复核**：`tmp2/count_midi.py` 自写 MIDI 解析，统计 note-on 总数/通道/音域，与解析器结果互证。
7. **音域体检**：钢琴 A0–C8（21–108）、小提琴 ≥G3（55）、中提琴 C3–C6（48–84）、大提琴 C2–C6（36–84）。

### 1.1 一个工具坑（影响生产者自述的可信度，不影响结论）

项目自带 `local/workbench/tools/midi_pitch_check.py` 解析 MIDI 时**在 meta 事件（0xFF）后漏读了 meta type 字节**，把 type 当长度跳过，导致大量音符被吞。实测：

| 文件 | `midi_pitch_check.py` 报 | 真实 note-on 数（自写解析器） |
|:--|:--|:--|
| `fence1.mid`（莫扎特） | 95 音（ch1 62 / ch2 33） | **113 音（ch0 71 / ch1 42）** |
| `fence2.mid`（贝多芬） | **7 音**（只有 ch4） | **50 音（10/10/10/20）** |

所以 `核对记录.md` 里莫扎特「音符总数 95、右手 62、左手 33」是**工具 bug 的产物**，不能当作音符清点依据；贝多芬那组「50 音 / 10/10/10/20」恰好是对的（数值与我实测相同）。

### 2.3 非音高差异（都不构成错音，供主控取舍）

1. **速度数值**：被测件 `\tempo "Andante cantabile" 4 = 80`；kern-ABC 第 20 行是 `1/4=88`，OMT MusicXML 第 151 行是 `<per-minute>80</per-minute>`（`beat-unit=quarter`）。→ **源间不同（88 vs 80）**，被测件与 OMT XML 一致；谱面插图只有 `Andante cantabile`、无节拍机标记，两个数值都属编辑性。**若交付要求「速度与 kern 源一致」，需改成 88 或注明依据 OMT。**
2. **末小节收口**：kern-ABC 的 bar 8（第 41/42 行）是**首结尾**，只有 1.5 拍（`c2z & c2x`），并带反复记号 `:|]|:`（回头接弱起）；被测件把 m.8 补足为完整 3 拍（`c''4 r2` / `<c' e'>4 c8 r4.`），末尾用 `\bar "||"`。OMT XML 同样把 m.8 补满（其 `m.8` 事件止于 1.5 拍、其余以休止填充），**所以「补满」有依据**；但 `\bar "||"` 会把「这是首结尾、后面要反复」这一信息抹掉。建议在本段下方加一行「mm.1–8 为首结尾、原谱此处反复」的注解，或改用 `\bar ":|."`。

## 4. 源之间的冲突与采信

### 4.1 贝多芬 m.4、m.8 落音的时值：四分 vs 八分

| 依据 | m.4（大提琴 C4） | m.8（四声部） | 性质 |
|:--|:--|:--|:--|
| kern `quartet02-4.krn` 第 29–30 行 / 第 44–45 行 | `4c\` ＋ `4r`（四分＋四分休止） | `4D\`/`4F#/`/`4d/`/`4d/` ＋ `4r`（四分＋四分休止） | 唯一异读 |
| kern-ABC（`0008-…mvt 4.abc` 第 40 行 `C2z2`、第 53–56 行 `D2z2` 等） | 四分＋四分休止 | 四分＋四分休止 | 与 kern 同源，**不独立** |
| DCML `n02op18-2_04.notes.tsv` | C4 `duration_qb=0.5`（八分） | 各声部 `0.5` | 结构化 |
| DCML `_04_reviewed.mscx` | `[midi60:eighth][rest:eighth][rest:quarter]` | 同上 | 校订谱面 |
| OMT `beethoven_18_2.xml` + 谱面插图 | 八分＋八分休止＋四分休止 | 同 | 独立谱源谱系 |
| **被测件** | `c'8 r8 r4` | `d8 r8 r4` 等 | 与后三份一致 |

**采信：八分。** 理由：kern 与 ABC 是同一谱系（ABC 由该 kern 转出，不构成第二份独立证据），而 DCML（含校订 mscx）、OMT XML、OMT 谱面插图三方一致；我还把 OMT 谱面插图放大到能看清符尾与休止符号——m.4 的大提琴是「带符尾的八分音＋八分休止＋四分休止」，m.8 四声部同样。**被测件的取法正确，无需改动**；建议在 `.ly` 注释里登记这条异读，免得后续被误「改回」四分。

### 4.2 莫扎特 m.5 伴奏和弦的谱表归属

kern-ABC（第 36 行 `[=B,4D4F4][C2E2][K:clef=bass]`）记在 V2（左手）；OMT XML 放在 staff 1；OMT 谱面插图也把它们印在右手高音谱表内（左手该小节无音符）。**被测件与 OMT 两源一致**，判为排版选择。若哪天以 kern 为准返工，只需把这两个和弦挪到 `leftHand` 的 m.5（并把 `R2.` 移到右手），音高音值一字不用改（左手已是高音谱号）。

### 4.3 贝多芬速度：192 vs 120

kern `*MM192` 与 ABC `1/4=192` 一致，被测件取 192；OMT XML 里有一个 `quarter=120` 的 `<metronome>`，但 OMT 谱面插图只印 `Allegro molto quasi Presto`、**并无节拍机数字**，且 120 与「molto presto」的音乐性格明显不称。判 OMT 的 120 为其 mscx 编辑残留，**被测件取 192 可接受**。

### 4.4 莫扎特速度：80 vs 88

kern-ABC `1/4=88`；OMT XML `<per-minute>80</per-minute>`（quarter）。被测件取 80。**源间冲突、谱面无标记**，两者都属编辑性数值，不影响放行；若要「与 kern 源一致」则应改 88。
