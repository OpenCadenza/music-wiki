## 0. 核验方法与工具说明

本报告不依赖人工视读，采用「解析 → 规范化 → 逐小节多重集合比对」的机械核验，脚本留在
`local\workbench\scores\verifier\tools\`（`cmp_staff.py` / `cmp_xml.py` / `kern2.py` / `ranges.py`）。

1. **LilyPond 侧**：自写绝对音高解析器，逐事件取出 `(音高 MIDI, 时值)`，按 `|` 切分小节，按变量（声部）分组；
   **应用 `\key` 调号**（关键：LilyPond 中 `\key g \major` 下裸写 `f` 即 F♯，`\key df \major` 下裸写 `a` 即 A♭）。
2. **kern 侧**：解析 `**kern`，按 `*staffN` 归属谱表，处理 `*^` 分裂与 `*v` 合并（**合并须按连续 run 折叠**，否则 m.5 之后全谱表错位），跳过 `4rA`/`2rBB` 这类带位置标记的休止。
3. **MusicXML 侧**：`<part>/<measure>` 顺序事件，正确处理 `<chord>`、`<backup>/<forward>`、`<grace>`。
4. 比对粒度：**每小节 × 每谱表的音高多重集合 + 时值多重集合**；不一致时再输出「仅见于源 / 仅见于 .ly」清单。
5. 音域用同一解析器统计每声部实际最高/最低音。

> 说明：早期草稿因为忽略调号、误读 `''+`（正则要求 ≥2 个撇号）、`<< … \\ … >>` 被当成和弦、以及 `*v` 合并 bookkeeping 四处缺陷，曾产生大量假阳性。上述缺陷已全部定位修复；本报告数据为修复后的结果，且**同一处差异必须在两路源（kern 与 MusicXML）同时复现**才判为真错。

## 2. Beethoven Op.135 III. Lento assai, cantante e tranquillo，mm.1–12

**来源核验**（三源齐备）
- kern：`resources\scores\source-packages\beethoven-score-sources\beethoven-string-quartets-main\beethoven-string-quartets-main\kern\quartet16-3.krn`
  文件头：`!!!OMV: Mvmt. 3`、`!!!OMD: Lento assai, cantante e tranquillo`、`*k[b-e-a-d-g-]`、`*D-:`、`*M6/8`、`*MM40`

**拍号/调号裁定（针对任务中的疑问）**
- **拍号是 6/8，不是 3/2**。kern `*M6/8`、OpenScore measure 1 的 time 均为 6/8；每小节 = 3 个四分音符 = 0.75 全音符，与 `.ly` 全部 12 小节总时值 0.75 一致。
- **调号是 D♭ 大调** ✓（kern `*D-:`、`<fifths>-5</fifths>`）。
- `.ly` 的这两项都正确。

**逐音结果**（4 声部 × 12 小节 = 48 组）

一致，除下列 4 处。**4 处均由 kern 与 OpenScore 双双复现**（DCML 备份印证），故判为真错。
共同病因：**依赖调号但漏写变音/八度记号**，LilyPond 按调号渲染成了别的音。

| 声部 | 小节 | .ly 现写 → 实际渲染 | 应为 | 三源证据 |
|------|------|---------------------|------|----------|
| Vn1 | m.10 | `af'8` → **A♭4** | **A♭3**（`af8`） | kern `(8A-/L` = A♭3；DCML midi=56 name=Ab3；OpenScore midi 56 |
| Vn2 | m.7 | `a4.` → **A♭3** | **A♮3**（`an4.`） | kern `4.An`（an = 还原）；DCML midi=57 name=A3；OpenScore midi 57 |
| Va | m.8 | `d4` → **D♭3** | **D♮3**（`dn4`） | kern `(4Dn/`；OpenScore D3（`<alter>` 缺省=0） |
| Vc | m.8 | `d,4.` → **D♭2** | **D♮2**（`dn,4.`） | kern `4.DDn/`；OpenScore D2 |

> 注：Va/Vc 的 m.8 是同一个「升四度」和声点，两处必须一起改，否则四重奏会半音打架。

### 2.1 专项裁定一：生产者称「Kern m.7 次中音缺附点、按 OpenScore 取 A♭ 附点四分」

**该说法不成立，且若照此实施会引入错误。**

1. **kern m.7 并不缺附点。** kern 该小节（第 4 栏为次中音/第二小提琴，第 5 栏起为拆分声部）
   `(4.An/` 与 `4.B-/` 均为 `4.`（附点四分），合计 0.375+0.375 = 0.75，正好填满 6/8 小节，**结构完整**。
   DCML 同音 `duration_qb=1.5`、`duration=3/8`，也是附点四分。三源中没有任何一处缺附点。
2. **音高是 A♮，不是 A♭。** kern 写作 `An`（显式还原号），DCML `midi=57 / name=A3`，OpenScore `midi=57`。
3. 而 `.ly` 现写 `a4.`——在 `\key df \major` 下 LilyPond 渲染为 **A♭3**，即**恰好实现了生产者自述的错误结果**（写 A♭）并使其不可见。
4. 正确做法：写 `an4.`（附点四分、A 还原）。这样既满足「附点四分」，又满足三源的 A♮。

也就是说：**结论音高该是 A♮、时值该是附点四分；生产者的时值判断对了一半（本来就对），音高判断整个反了，且实现成了错误音高。**

### 2.2 专项裁定二：生产者称「大提琴 mm.3–5 为双声部（持续低音＋进行低音）」

**该说法成立，且 `.ly` 实现正确。**

- **kern 结构证据**：大提琴所在 spine 在 m.3 行首 `*^` 分裂为二，至 m.5 末尾 `*v *v` 合并回一，正好覆盖 mm.3–5。
- **DCML 证据**：m.3 staff4 两行并存——`voice=1: Db2 (dur_qb 1.5)` + `voice=2: Ab2 (dur_qb 3.0)`，另有 `voice=1: Eb2 (dur_qb 1.5)`。
- **OpenScore 证据**：m.3–5 该声部每小节时值和 = 1.5，即两个 0.75 叠置。
- **`.ly` 实现**：`<< { af,2. } \\ { df,4. ef,4. } >>` → 持续 A♭2 附点二分 + 进行 D♭2/E♭2；解析后每小节总时值 1.5，与源逐小节完全相等 ✓

**音域**：Vn1 A♭3–F5 ✓；Vn2 A♭3–A♭4 ✓；Va C3–F♯3 ✓；Vc C2–F3 ✓。全部合规（Vn1 下限 A♭3 正是 m.10 应为的音，进一步印证 2.1 表第一行）。

**编译**：exit=0，0 warning。

**速度存疑（非阻断）**：`.ly` 写 `\tempo "…" 8 = 50`，即每八分音符 1.2 s、每小节 7.2 s；而源播放速度为 52.5 四分/分 ≈ 每小节 3.4 s，kern `*MM40` 亦指向更快的读数。`8 = 50` 使实际速度慢约一倍，疑为 `4 = 50` 之误。建议核对后改 `4 = 50`（或直接删去数字）。

**结论**：**修正 4 处后（并建议顺带核对速度数字）方可回填**。特别是 m.7 必须写成 `an4.`，绝不能写 A♭。

## 5.（追加）Beethoven Op.67 II mm.205–209（大管主题变体）—— 判定：**不可用（仅单声部）**
