## 1. 核验方法（与我做了什么）

1. **自行解包权威源**：用 `Expand-Archive` 把三份 `.mxl` 解到 `verifier/s9/x_a|x_b|x_c/`，不碰生产者的 `src/`。
2. **MusicXML 结构化转写**：`dump_mx.py` 按 MusicXML 游标模型（divisions=48、`<chord>`/`<backup>`/`<grace>`）还原每个音符的绝对 onset，输出可读清单（`full_b.txt`）。
3. **`.ly` 独立解析比对**：`ly_cmp2.py` 自写 LilyPond 子集解析器（绝对音高、和弦、附点、`-.` `->` `\tenuto`、slur、tie、`\grace`、休止），按 `|` 切小节，与 XML 逐小节比对
   **（onset、音高集合、休止标志、时值、附点数、奏法集合、tie、slur 起止、grace 标志）** 十元组。
4. **MIDI 反向验证**：`lilypond` 实编译出 `build/v.mid`，自写 SMF 解析器，按 384 tick/四分音符还原每个 note-on 的绝对位置，与 XML「发声音符表（已合并延音线）」比对 onset+pitch。
5. **三源交叉**：`three_way.py` 用规范化键（忽略所有排版坐标）比对 212 小节 × 4 声部。
6. **版式目检**：PyMuPDF 渲染 PDF → PNG 目视检查（单页、4 系统、小节线、连谱括号、速度标记位置）。

## 5. 差异清单（逐条）

### D1【重大 · 必改】mm.1–21 的 13 条力度记号全部丢失

- 源（三份一致）在 mm.1–21 有 `p`×4 处、`pp`×3 处（见 §2.3），成品 `.ly` **没有任何 `\p`/`\pp`**，渲染出的 PDF 也无一处力度。
- 生产者 `核对记录.md` §4.6「mm.1–21 全段没有任何力度记号（前 60 小节都没有）」与 §7.7「谱面没有 p，那是演奏惯例」**均不成立**：全文件 132 个 `<dynamics>` 的**第一个就在 m.1**，且 m.3 大提琴进入即标 `p`。其 `dump_notes.py` 显然只打印了 `<words>`，没打印 `<dynamics>`。
- 影响：文章的论点是「钢琴**极轻**短促跳音」，而谱面上恰恰没有 `p/pp`，谱例反而不能支撑正文。且源的力度布局本身就是「p（m.1 钢琴 / m.3 大提琴）→ pp（m.14 大提琴 / m.15 钢琴回响）→ p（m.20）→ pp（m.21 集体）」的**回声式衰减结构**，这是很好的论据，丢掉可惜。
- 修法：在对应位置插入 `\p` / `\pp`（建议写成 `pianoRH`/`pianoLH` 各一处、大提琴按 m.3/14/20/21、小提琴 m.21），注意 PianoStaff 两行同一拍各标一次会在同一 x 位置上下各排一个，可按源照排。

### D2【真差异 · 建议改】大提琴 m.16 连音线起点晚一个十六分

- 源：`m.16` = G2 四分（tie start）→ G2 十六分（tie stop）→ **G2 十六分（`slur type="start"`）** → A2 十六分 → B2 十六分（`slur type="stop"`）。
  即连音线从**第三个音**起，覆盖 G2–A2–B2。
- 成品：`g,4~ g,16( g,16-. a,16-. b,16-.)` —— 连音线从**第二个音**（被延音线连住的那个 G2）起，覆盖四个音。
- 视觉后果：连线左端早一个十六分（源 PDF 坐标 `default-x` 68.51 → 86.13，差约 17 单位）。
- 修法：`g,4~ g,16 g,16-( a,16-. b,16-.)`。

### D3【建议改】谱面排出了源没有的节拍机标记

- 源**只有** `<words>Andante con moto</words>` + `<sound tempo="40">`，**无 `<metronome>`**。
- 成品 PDF 上排出了粗体 "Andante con moto" 和 "♩ = 40" 两行（见 `build/v-p0.png`）。
- 严格照源的话，40 应作为**不排印的播放速度**：`\tempo 4 = 40` 改为
  `\set Score.tempoWholesPerMinute = #(ly:make-moment 10 1)`（40 qpm = 10 wholes/min），谱面只留文字。
- 若主控认为"给读者一个参考速度"更重要，则应保留现做法，但**在图注里写明"♩=40 取自 XML 播放值，非印谱标记"**——不能让它看起来像原谱标记。

### D4【说明性，可不改】MusicXML 的 courtesy accidental 未复现

- 源在多处标了 `<accidental>natural</accidental>`（m.5/13/14/16/18/20 等，B♮ 与 A♮）。在 c 小调里 B♮/A♮ 是调内音，LilyPond 按规则不排还原号，成品谱因此比 OMR 源"少"这些提示性还原号。
- 这**不是错音**（音高一致），只是排版取舍。若要像素级贴合 OMR，需要手动 `\natural`；一般不必。

## 6. 速度判断

### 6.1 40 是不是导出默认值？

**不是。** 依据：

1. **MuseScore 的默认播放速度是 120 bpm**，不是 40。`<sound tempo>` 导出的是谱面播放速度属性，要变成 40 必须有人设过（或从某个来源继承）。
2. 三份源里 40 都只出现一次、位置在 m.1 的第一条 direction 里，与 "Andante con moto" 文字同一 direction —— 典型的"上传者按演奏时长配的播放速度"。

### 6.2 但 40 与 "Andante con moto" 的字面含义不符，是否该改？

我做了两条独立核算：

**(a) 时长反推。** 本乐章 212 小节 × 2/4 = **424 个四分音符**。

| 四分音符/分钟 | 乐章总时长 |
| --- | --- |
| 40 | 10 分 36 秒 |
| 44 | 9 分 38 秒 |
| 46 | 9 分 13 秒 |
| 60 | 7 分 04 秒 |
| 80 | 5 分 18 秒 |

**(b) 实际录音时长**（在线核查，见文末来源）。Andante con moto 的常见录音：
Isaac Stern / Istomin / Rose = **9:37**；Beaux Arts Trio = **9:41**；Capuçon 兄弟 / Braley = **8:43**；harmonia mundi（period instruments）= **9:27**；IMSLP 现场录音 = **9:52**。
→ 实际演奏的等效速度约 **♩ = 43–49**。

**两个结论：**
1. 生产者 `核对记录.md` §3 里「此乐章常见演绎在四分音符 **60–80** 一带」**是错的**（60–80 会让乐章只有 5–7 分钟，比任何录音都快 30% 以上）。若据此把 `4 = 40` 改成 60–80，会把它改成明显偏快的速度。
2. **40 只比实际演奏慢约 8–10%**，对一个"照源取值"的谱例完全在可接受范围；它很可能就是上传者照某张录音配的。

### 6.3 结论

> **照源取 40（可接受，不建议改数值）。**
> 但必须处理**呈现方式**：40 在源里是"不排印的播放速度"，成品把它排成了节拍机标记（D3）。要么改成隐藏的 `tempoWholesPerMinute`，要么在图注注明"取自 XML 播放值"。
> 不建议改成 60–72 之类的"更符合 Andante 字面"的数——那会把"与源一致"变成"编者推测"，且会与实际演奏速度偏离 30% 以上。

### 8.3 「主题真正头部在 m.4（装饰音后），m.3 两个 g 是引导」

**这是解释，不是谱面事实；我的独立判断是"与记谱相容，但不宜写成事实"。**

- 支持生产者的记谱证据：m.3 的两个 G3 自带一条连音线（slur 只覆盖这两个音，`start→stop` 都在 m.3 内），m.4 另起一条新连音线（C4→A♭3）。记谱上确实是**两个分开的发音单元**，而且 m.3 两个音都是断奏、m.4 的主题音不带断奏——记谱把"宣布"与"歌唱"分开了。
- 反对"引导"说的证据：m.3 的两个 G3 落在 **2/4 的第 1、2 拍两个强拍**上，是**正式进入**，不是弱起/引子；XML 里也没有任何"引子"迹象。
- 结论：**无法由 XML 判定"哪里算主题头部"**（这属于分析判断）。若正文要写，建议写成「主题由 m.3 的两个强拍 G 音宣告、在 m.4 的装饰音后展开为歌唱性旋律」；引用范围以 **mm.3–4** 起最稳，不要单引 m.4。

### 8.4 其他与文章冲突的点（附带发现）

1. 文章行 137 称「舒伯特著名的 **C 小调稍快板**乐章」。"稍快板"（Allegretto）与事实不符：源速度值是 **♩=40**（实际演奏 ♩≈43–49，9:30 左右的乐章），这是**葬礼进行曲式的慢速行板**——舒曼的著名评语也正是"一声叹息升到尖锐的痛苦"，harmonia mundi 的唱片说明直接称它 "funeral march-like Andante con moto"。建议改为"c 小调的行板/葬礼进行曲式乐章"。**注意文章自身第 143 行已经写了"规整的丧葬进行曲节奏"**——"稍快板"与"丧葬进行曲"在同一个案例里互相矛盾，删掉"稍快板"即可自洽。
2. 文章行 161 的判定流程写「大提琴音高是否处于 C2–G3 区间？…触发冲突：上浮至 G3–C5」——本乐章实际最高只到 **E♭4**，写 G3–C5 会高估半个八度以上。

## 9. OMR 风险点判断

### 9.1 m.14–16 大提琴 G3→G2→G3 八度跳（生产者怀疑 XML 把双声部并成一个 voice）

**我的判断：XML 内部自洽；生产者的「符干方向互相矛盾」这条理由不成立；"是否原本双声部"无法由 XML 判定，但证据倾向"单声部"读法。**

证据：

1. **结构自洽**：mm.14/15/16 三小节都只有 `voice=1`，**没有 `<backup>`/`<forward>`**，每小节音符时值总和精确 = 2.0 qn；没有任何同拍重叠音。也就是说 XML 呈现的是一个"老实"的单声部，而不是一个被压扁的双声部（压扁通常会在别处留下超长/超短小节或 backup）。
2. **符干方向不是并声部证据**：m.15 的 G2 `stem=up`、G3 `stem=down`；m.16 全 `stem=up`。这完全符合"按音高在五线谱上的位置自动决定符干"的规则（G2 偏下→上，G3 偏上→下）。**不是**"互相矛盾"。生产者的这条怀疑可以撤销。
3. **连音线/延音线贯通**：m.16 的 G2 四分用 `tie` 连到后面第一个十六分，说明 OMR 把它当成一条连续线，而不是两条独立声部。
4. **音乐逻辑支持单声部**：m.16 的 `G2 → G2 → A2 → B2` 接 m.17 的 `C3`，是教科书式的**上行终止低音**（G–G–A–B→C）。
5. **钢琴同时刻有同型**：m.15/16 钢琴右手 `g′8(accent+staccato) → g4`、左手 `g8 → g,4`，即钢琴在同一时刻做 `g′→g` / `g→g,` 的**八度下行应答**；m.16 右手 `g4` 还带延音线进 m.17。说明"八度落差"是这一段**共同的写法**，不是大提琴一处孤立的 OMR 事故。
6. **剩下的疑点**（诚实记录）：若原谱真是双声部，重叠点只可能在 **m.15 第 1 拍**（下声部 G2 与上声部 G3 同时）；单声部读法要求演奏者在 3 拍内做两次八度跳（G3→G2→G3→G2），对主题性旋律略嫌跳跃。**这需要印谱才能定案，XML 自身无法判定。**

→ 处置建议：**保留现状（单声部、不强制符干）**；若正文要对 mm.14–16 的音区下强断言，避开这 3 小节或加脚注。

### 9.2 m.1/2/6 第四拍「附点十六分 + 三十二分」

**我的判断：XML 内部自洽，且判定为"很可能就是原谱如此"，但仍是建议对印谱复核的项。**

证据：

1. **时值精确**：每小节 = 八分 ×3（1.5）+ 附点十六分（0.375）+ 三十二分（0.125）= **2.000**，正好填满 2/4。
2. **符杠层级自洽**（这是最关键的一条）：m.1 钢琴右手最后一组是
   `附点十六分`：`beam 1=continue, beam 2=begin`；`三十二分`：`beam 1=end, beam 2=end, beam 3=backward hook`。
   MuseScore 只有在"附点十六分 + 三十二分"这种真实时值组合下才会生成这种「二级杠起 + 三级杠反向钩」的结构；若 OMR 把两个十六分误读成一个附点十六分+三十二分，`<duration>`（18 / 6）与符杠层级通常会对不上。**这里是全对上的。**
3. **同一音型在别处复现**：m.21 小提琴与大提琴进入时又是 `八分×3 + 附点十六分(tenuto+accent) + 三十二分(staccato)`——同一"snap"音型在主题进入处再现，说明这是**作品的写法**，而不是某小节的识别噪声。
4. **三份源一致**：98,865 B 与 99,688 B 两份在 212 小节内**零差异**，125,808 B 只多文字。三份都保留这个音型。
5. 反面：这确实是 OMR 的高危节奏型（把符尾/符点读错），且 mm.1/2/6 的左手是同一时值的单音，两处独立错成一致的概率不高但非零。

→ 处置建议：**照录，不改**；在核验记录里保留"建议对照印谱确认 m.1/2/6 第 4 拍"这一条。
