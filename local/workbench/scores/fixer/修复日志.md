## 5. 与核验报告的分歧（未采用的三组修改，逐条给证据）

### 5.1 Op.135：报告第 8/9/10 项（`an4.` / `dn4` / `dn,4.`）不成立

报告的前提（§0 方法第 1 条）是“**关键：LilyPond 中 `\key g \major` 下裸写 `f` 即 F♯**，故 D♭ 调下裸写 `a` 即 A♭”。
本轮实测该前提为假：

```lilypond
% local\workbench\scores\fixer\tmp-key-test.ly
\score { \new Staff { \key df \major a'4 d'4 g'4 c'4 e'4 b'4 f'4 } \layout { } \midi { } }
```
编译后 MIDI：`A4(69) D4(62) G4(67) C4(60) E4(64) B4(71) F4(65)` —— **全部为还原音**。
即 LilyPond 音名是“绝对音高 + 显式变音”，`\key` 只决定谱面调号与临时记号的显示，不改变音高。
（这也正是本谱所有降号都显式写成 `df'/ef'/gf'/af'/bf'` 的原因。）

由此：

1. `a4.`（m.7 Vn2）实际发 **A♮3(57)**、`d4`（m.8 Va）实际发 **D♮3(50)**、`d,4.`（m.8 Vc）实际发 **D♮2(38)**，
   与 kern（`4.An` / `(4Dn/` / `4.DDn/`）和 OpenScore（A3/D3/D2）**本来就一致**。
   实测 MIDI 印证（本轮改动只动了 m.10 的 Vn1，m.7/m.8 各轨未受影响）：
   `bar7 trk2 = A3(57)`、`bar8 trk3 = D3(50)`、`bar8 trk4 = D2(38)`。
2. 报告建议的写法 `an4.` / `dn4` / `dn,4.` 在 `\language "english"` 下**不是合法音名**，实编译报
   `error: not a note name: an`（见临时测试，已删除测试文件）。
3. 报告表里 `ly-only: Ab3 / C#3 / C#2` 来自核验脚本自身的“应用调号”假设，属**测量端 bug**，不是成品缺陷：
   `verifier\tools\cmp_staff.py:36-66`（`KEYSIG` / `set_key` / `detect_key`，第 65–66 行对未写变音的音名套用调号）
   与 `cmp_xml.py:94`（`C.detect_key(text)`）都按“裸音名继承调号”计算 `.ly` 侧音高，而 LilyPond 并不这样解释。
   同一脚本在改后仍报这三条（因它仍把 `a`/`d` 算成降音），而真实 MIDI 与两路源一致。

**结论**：这三处**保持原样**，并把这些信息写进谱头注释（§2.4），避免下一轮再按同一错误前提“修”一次。

### 5.2 Brahms：报告的“大提琴 m.4 末–m.8 整体高八度”不能复现

报告表格的关键一步是 `d,8)` 记为 **D3**（并称“`bes'16.` 与 `d,8)` 的八度标记是显式的，其后 `d16. ees32`
只能解析为 D3/E♭3”）。但 `d,` 是 `\relative` 里的**相对**八度记号，其基准是前一音 A♭4：

```lilypond
% 底本原句（Violoncello，mm.4-5）：bes'16. aes32 d,8) d16.[( ees32]) f4 aes16.( g32) …
```
用 LilyPond 自身解析（`tmp-brahms-base.ly`）得到的绝对音高为
`B♭4 A♭4 **D4** | **D4** E♭4 | **F4** A♭4 G4 …`：A♭4 到 D 恰好是三全音，LilyPond 取**上行**八度，
再经 `,` 降一点 = D4（并非 D3）。所以：

- m.4 末 `d16. ees32` = D4 E♭4，m.5–m.8 的 `f4 / ees4 / c8. / d8` 随之全部在 **C4 八度** —— 与现行 `.ly` 相同；
- 报告据此要求“把 m.4 末与 mm.5–8 全部降八度”，会让整段比底本低八度（12 个音），故**不采用**；
- 真正需要改的只有 §3 表里的 5 个音（大提琴 m.4 两个 D、m.7 的 B；大管 m.7 的 A♭、m.8 的 C）。
