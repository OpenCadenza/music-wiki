## 一、总体结论

**「音高/时值/声部/连音/tuplet：一致（0 差异）」；「记谱层：2 处必须修 + 2 处建议补」。**

- **必须修（2 处，均为"读者能直接看出来"的问题）**：
  1. **谱面小节号错**：交付 `.ly` 内小节计数为 1–20，LilyPond 默认在行首印 **3 / 5 / 7 / 9 / 11 …**（见渲染件），而这是**印刷谱 m.23–42**。读者会按 3、5、7 去对谱，全部错位 20 小节。
  2. **m.37 与 m.41 的渐强（`<`）未转译**：底本 `**dynam` 在 m.37 首记录与 m.41 首记录各有一个 `<`；交付件两处都没有（`核对记录.md` §4-5 却声称已"逐条照录"）。m.38 的 `sf` 前少了渐强踏板，是可直接听出的力度差异。
- **建议补（2 处）**：① 圆滑线（m.35→36、m.37→38、m.39→40、m.41 内，共 7 个标记 / 4 条乐句线）未转译——本段正是以 "dolce e molto **legato**" 为论据的段落，建议至少补 m.35–41 的乐句线；② m.42 首组 G♯3 的**谱表归属**：音高已证实为 G♯3（非 G♯4），但第二源 A 把它写在**左手**谱表（与 E2+E3 同谱表），kern 写在右手 spine，交付件随 kern 写成右手和弦——两种都可辩护，若正文/读者按"双手分工"论述需注明。

## 六、记谱层：2 处必须修（附实测修改方案）

### 6-1 谱面小节号错（必须修）

- 现状：`.ly` 内 m.1–20 对应印刷谱 m.23–42，LilyPond 默认按内部计数印行首小节号 → 渲染件上出现 **3 / 5 / 7 / 9 / 11 …**。
- **已实测的修法**：在 `\global` 最前面加一行

```lilypond
\set Score.currentBarNumber = #23
```

  实测结果：行首小节号变为 **23 / 25 / 27 / 29 / 31 …** ✓，编译 0 error / 0 warning，音高时值不受影响。
  （注意：#23 而非 #22——`currentBarNumber` 设的是"当前是第几小节"，实测 #22 会印成 22/24/26…）

### 6-2 m.37 与 m.41 的渐强未转译（必须修）

- 底本 `**dynam` 实测：`p`(23) `<`(27) `f`+`sf`×3(28) `>`(31) `p`(33) **`<`(37)** `sf`+`>`(38) `p`(39) **`<`(41)** `p`(42)。
- 交付件有 23/27/28/31/33/38/39/42，**缺 37 与 41**（`核对记录.md` §4-5 把 `<`(m.37) 列为"逐条照录"，与实际不符）。
- **已实测的修法**（加 `\!` 收束发夹，否则 LilyPond 报 "unterminated crescendo"）：

```lilypond
% m.37（原行）
<a' b'! ds''>2\< <b' e''>4 <cs'' e'' fs''>4\! |
% m.41（原行）
<< { <e gs>4\< <fs a>2.\! } \\ { <b,, b,>1 } >> |
```

  实测：0 error / 0 warning，且与底本的逐音比对仍为 0 差异（渐强只改 MIDI 力度，不改音高/音位/时值）。

### 6-3 谱号（本段正确，供对照）

底本谱号轨迹与交付件逐处一致：右手 m.23–29 高音（`*clefF4` 在 m.29 末 → m.30 低音）→ **m.30 低音** → m.31 起高音；左手 m.23–34 低音 → `*clefG2`（m.34 末）**m.35–36 高音** → `*clefF4`（m.36 末）**m.37 低音** → `*clefG2`（m.37 末）**m.38 高音** → `*clefF4`（m.38 末）m.39 起低音 ✓

## 十、未能核验 / 局限

1. **未与印刷谱比对**（库内无 Op.53 扫描件）：结论是"对底本 kern 的忠实度"，第二源 A/B 为 musescore.com 用户转录（`is_official=False`），仅作旁证。
2. **B 源未做逐音复核**：B 为整部 Op.53 单 part、含 X1–X4 反复结尾，`<backup>` 与多声部交织使我的单游标 MusicXML 解析器在该文件上错位；本轮以 A 源作独立旁证（A 在 4 个疑点上全部与 kern 一致），B 仅采纳生产者记载。
3. **速度 144**：只出自 kern `*MM144`（MuseData 转写值）。A 的 `<sound tempo>` 起始 160（其后 140/120…），B 有整段 tempo 自动化（含 144，但起始 168）；印刷原版此处无节拍机数字 ⇒ 谱面印出的 "(♩=144)" 建议注明来源或只印文字。
4. **`z` / `` ` `` / `\` 三类 MuseData 遗留记号**：本轮逐处验证其**不改变音高与时值**（`(<2E`、`2D#<`、`8D#\`` 等），故解析安全；但其确切语义仍未确证，生产者 §6-3 的保留态度合理。
