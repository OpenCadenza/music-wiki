# 谱例交付方法与核对规范（D1 预演总结）

本文档总结从原始谱库数据（Kern / ABC / MusicXML / IMSLP）到高质量、符合 VitePress 知识库规范的 LilyPond 2.26.0 谱例交付流程。

---

## 一、谱源 → 片段的转换路径

1. **谱源定位与检索**：
   - 优先查本地已整合与预备的结构化谱库：
     - `local/resources/scores/`（已封装规范的示范谱例目录）
     - `local/origin_resources/corpus/lilypond/`（Mutopia 权威工程，可直接提取原作者校对好的多声部框架）
     - `local/origin_resources/corpus/abc/` 及 `local/resources/scores/source-packages/`（Humdrum Kern、DCML MuseScore 3、ABC 转录本）
   - 当本地缺失时，按 Exa → Tavily → Jina 检索 Mutopia / IMSLP / Kern 权威版本并保留来源信息。

2. **片段提取与对齐**：
   - 根据学者请求明确作品号、乐章、拍号与小节范围（注意区分弱起小节与完整小节计数）。
   - 核对多声部对齐（Spine 对齐）：在 Humdrum Kern 中，通常最左侧为低音声部（Cello/Bass），依次往右为内声部与高音声部（Viola, Violin II, Violin I）。
   - 检查调号变化（`*k[...]`）、拍号变化（如 4/4 切换为 3/2 `*M3/2`）与速度记号（`*MM...`）。

3. **编码转换为 LilyPond 2.26.0**：
   - 统一采用 `\version "2.26.0"` 与 `\language "english"`。
   - 包含完整的 `\header`（`title`, `subtitle`, `composer`, `tagline = ##f`）。
   - 明确设定 GM 乐器编号（0–127 基准，如 Piano 为 0, Violin 为 40, Viola 为 41, Cello 为 42）。
   - 保留速度记号（`\tempo ...`）、表情记号、连线、顿音与弱起声明（`\partial`）。

4. **编译器测试与验证**：
   - 使用完整路径 `E:\GreenSoftware\lilypond-2.26.0\bin\lilypond.exe` 进行本地编译。
   - 必须通过解析与图形布局，生成同名 `.pdf` 与 `.mid` 产物。

## 二、按原谱严格核对的七大要素

**注意：LilyPond 编译通过仅代表语法无误，绝不等于音乐内容正确！必须回原谱逐项核对：**

1. **作品与乐章**：确认作品编号（如 Hob. XVI:27, K. 283, Op. 74, Op. 135）与乐章标题（如 III. Presto, I. Allegro, IV. Grave）。
2. **小节范围 (Location)**：明确起止小节。对于含弱起小节的乐章，必须在 location 与注释中指明弱起时值（如 `\partial 8` 或 `\partial 4`），避免学者在曲式功能分析时产生小节编号位移。
3. **音高 (Pitch) 与升降号 (Accidentals)**：
   - 重点核对调外临时升降号（自然还原、重升重降）；
   - 警惕 `\relative` 模式下的八度跳跃偏差（如六度以上大跳易落入错误八度）。
4. **节奏与时值 (Rhythm & Duration)**：
   - 连音符（三连音、五连音）、附点音符与切分音的时值完整性；
   - 震音（Tremolo）与十六分音符密度的拍值匹配。
5. **声部完整性 (Voice Integrity)**：
   - 优先交付全声部总谱；
   - 若只能交付声部摘录，必须在 `title` 与 `location` 中明示“摘录（包含声部：...）”，**严禁改编、简化音高或自编织体冒充原作**。
6. **调号与移调上下文 (Key & Transposition)**：
   - 对移调乐器（单簧管、圆号等）必须指明是实音记谱（Concert pitch）还是移调记谱。
7. **速度与力度标记 (Tempo & Dynamics)**：
   - 原谱中的 $p, f, fp, sfz$ 以及渐强渐弱，准确还原作曲家戏剧意图。

## 三、代码围栏与站点检验规范

在 VitePress 文档正文中引用谱例时，必须严格满足以下硬性约束（与 `scripts/validate-content.mjs` 联动）：

1. **围栏属性格式**：
   - 使用 ````lilypond title="..." location="..."```` 或 ````abc title="..." location="..."````。
   - 属性名仅支持 `title`、`location`、`id`（且必须双引号包裹）。
   - **禁止**在围栏上方添加遗留的加粗标题行（`**标题**`），属性与加粗标题不能并存。
2. **版本声明唯一且精确**：
   - LilyPond 片段内必须有且仅有一行 `\version "2.26.0"`。
3. **防重复与唯一 ID**：
   - 全库严禁完全相同的谱例代码内容（哈希去重）；可选声明符合 `^[a-z0-9][a-z0-9._-]*$` 的稳定 `id`。

## 四、常见数据源的“坑”与避坑指南

### 1. Humdrum Kern 常见陷阱
- **八度记号（Octave Indicators）**：
  - Kern 使用字母大小写与重复表示八度：`CC` (C2), `C` (C3), `c` (C4 中央C), `cc` (C5), `ccc` (C6)。
  - 自动脚本极易在大小写混合时搞错绝对音高与相对八度。
- **时值记号（Duration）**：
  - 数字表示分母，如 `4` 为四分音符，`8` 为八分音符，`16` 为十六分音符；`4.` 为附点；`0` 为双全音符。
  - 注意休止符记为 `r`（如 `2r` 为二分休止符）。
- **连音与发音**：
  - `LL`, `JJ` 表示符杠（Beaming）起止；`(` 与 `)` 表示连线；`'` 表示断音；`\` 与 `/` 表示符干方向（不应转为音高）。

### 2. DCML / MuseScore TSV 常见陷阱
- **小节与和声展开**：
  - DCML 经常有 `_unfolded.harmonies.tsv` 与 `_reviewed.tsv`，前者展开了反复记号，小节号会变大；比对原谱时必须使用带物理小节标记的 measures/notes 文件。
- **和弦音切片**：
  - DCML TSV 中的 `notes.tsv` 按 onset 切片，装饰音（Grace notes）经常标记为特殊 onset 或负值，若简单遍历会遗失倚音。

### 3. "Kern → LilyPond 半自动转换" 的可行性判断
- **可行层面**：
  - 节奏结构、音符骨架与小节划分可以通过工具（如 `hum2ly` 或自编转换脚本）提取骨架，极大减少手工敲音符的工作量。
- **不可靠/必须人工介入层面**：
  - **移调与临时记号作用域**：Kern 每一小节的临时记号声明与 LilyPond 的按小节继承规则存在细微差异；
  - **连音线、指法与多声部穿插**：自动生成的代码往往充满冗余标记，排版可读性极差，且无法直接生成规范的 `PianoStaff` 或 `StaffGroup`；
  - **结论**：**可以利用 Kern 辅助提取音高与节奏骨架，但最终交付前必须经过人工重构、加入标准规范头并由 LilyPond 2.26.0 真实编译和对原谱复核，不可全自动无人值守生成。**
