# 研究归档

每篇成稿一条记录，由写出该篇的音乐学者维护，只写自己的记录。本目录进入 Git，是研究长期的存档；"谁正在做什么"这类连续状态改由 DSH Team 任务板承载，不再写在本目录。

## 一条记录写什么

- 学者与选题；最终的中心论证（一两句讲清要解释什么）。
- 实际采用的资料范围：真的读到的来源、章节／页段／谱面范围。与拟读不同就写实际范围。
- 正文位置：`content/` 下的文件路径与主要归属目录。
- 谱例：助手交付的共享谱例位置，或真实定位的占位与缺口（含"待定位"）。
- 未解决的缺口、可接受的局限。
- 状态：`已成稿，待本批复读` → 复读后更新为 `已复读`，并记必要修订。

从简，不写成文章模板，不复制正文内容，不做逐句出处表。文件名用 `<文章slug>.md`，与正文文件同名便于对照。

## 与任务板的分工

- 任务板（DSH Team）记在研过程：认领、认领中的问题、资料请求、交付、提交状态，做完即关闭。
- 本目录记长期依据：成稿后留下这一条，供后续复读、修订与追溯。

完整规则见[子代理工作流](../子代理工作流.md)与 [DSH 首批实施计划](../实施记录/2026-11-16-DSH首批/实施计划.md)。
