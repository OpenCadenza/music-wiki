# 派子代理写知识库：工作流

> 上一轮实际用过、跑出 37 篇正文 + 51 个谱例块的流程。
>
> **先说清楚**：这套流程的**机制**可以借鉴，但它有一个致命的输入假设——只给写手乐谱、
> 不给理论资料，结果理论全是写手编的。**第 9 节写了必须改的地方，先看那一节再决定怎么用。**

---

## 1. 一句话

**主控只做四件事：定选题、写任务书、卡质量、做整合。配货与写作彻底分开，由不同代理并行干。**

主控自己不动手写正文。一旦主控开始写，就没人卡质量了。

---

## 2. 三种角色与边界

| 角色 | 只做 | 绝对不做 |
| --- | --- | --- |
| **主控**（Lead） | 探源、定选题、写任务书、派活、验收、整合、构建、提交 | 不亲自写正文 |
| **配货员** | 下载乐谱、迁移编译、转音名、切片预演、写 INDEX | 不写文章、不碰仓库文件 |
| **写手** | 切片、写作、自己编译验证 | 不碰 `NOTICE.md`、不碰共用 `index.md` |

**边界为什么这么划**：三个角色都要改文件，但改的是不同文件。主控独占"共用文件"
（`NOTICE.md`、各分支 `index.md`），写手只碰自己的那一篇。这样并发才不出错。

---

## 3. 一轮的时间线

```
① 探源      主控列 Mutopia 目录，确认有没有机器可读的源
              ↓（没有源 → 只能写占位，先别派人）
② 配货      配货员：下载 → 校验大小 → 迁移 2.26.0 → 编译 → 转 english → 写 INDEX
              ↓（配货与写作并行，不必等全部配完）
③ 派活      主控按"已就绪的源"定选题、写任务书
              ↓
④ 写作      写手：读任务书 → 读已登记范围 → 切片 → 写作 → 自编译 → 交稿
              ↓
⑤ 验收      主控：字数、围栏属性、tempo、GM、与已登记范围是否重叠、编译
              ↓
⑥ 整合      主控：加 index 链接、写 NOTICE 两表、跑四步构建、提交
```

**关键**：②③④ 是流水线，不是瀑布。配货员在开下一个体裁时，写手已经在写上一个体裁了。

---

## 4. 任务书六项（照这个写，缺一项就出问题）

### ① 文件路径与 H1
直接给。让写手自己想标题，它会写成"贝多芬的某某风格"这种话题而不是动作。

### ② 必须讲清的三到五个点

**这是任务书里唯一真正重要的部分。** 写成**具体的音乐问题**，不要写成话题。

| ❌ 坏的写法 | ✅ 好的写法 |
| --- | --- |
| 讲清楚贝多芬的配器风格 | 三种做法各自适合什么段落；大提琴一唱中音区就空怎么处理；加倍什么时候会遮蔽内声部 |
| 分析这个乐章的结构 | 副部在第几小节进来、进来时低音在做什么；结束部靠什么和副部区分 |
| 讲讲赋格 | 五个声部按什么顺序进、每次低几度；多出来的内声部是和声填充还是分叉 |

判断标准：**如果你自己看着这一条写不出答案，写手也写不出来，它就会去写空话。**

### ③ 拟用谱例
作品、乐章、大致小节。不必精确到小节，但要给范围，否则写手会挑一个和别篇重叠的段落。

### ④ 源码位置与工具用法
绝对路径 + 切片命令。写手不应该花时间找文件。

### ⑤ 占位许可
必须原话写上：**"拿不到谱例就写占位，不要停工。"**
不写这句，写手会卡在找谱例上，或者更糟——自己编一段。

### ⑥ 格式三件套
围栏 `title`/`location`、`\tempo`、每个声部的 `% GM`。给编号表，别让它查。

---

## 5. 并行的规矩

| 并行什么 | 上限 | 为什么 |
| --- | --- | --- |
| 写手 | **≤2** | 一次派 4 个以上，出现过半数在交付前被系统中断、空手而归 |
| 配货员 | ≤2 | 配货是 I/O 密集，冲突少 |
| 配货 + 写作 | 可以同时 | 两者改的文件不重叠 |

另外：**不要派"探索型"任务**。写手不会自己去找资料，派它"研究一下这个体裁"等于让它编。

---

## 6. 共用文件的冲突处理

`NOTICE.md` 与各分支 `index.md` 是共用文件，多个写手同时改会互相覆盖。

**实际发生过**：两个写手同时改 `NOTICE.md`，表格被拼接坏掉，修了三次。

**现行做法**：写手**不改**这两个文件，在交稿回报里给出登记行（例如
`Op.37 i mm.1–8；mm.110–118`，来源 `mutopia-899`），由主控统一写入。

主控写入时也要小心：**按行插入，不要用全局字符串替换**。用 `.Replace()` 替换
`| \`mutopia-899\` |` 这类短模式，会误伤表格里其他单元格，把行拼坏。

---

## 7. 质量门（主控逐条查）

交稿后，主控对每一篇跑一遍：

| 检查 | 判据 |
| --- | --- |
| 汉字数 | 1500–3000（不含代码块） |
| 围栏属性 | 每个 lilypond 块都带 `title=` 与 `location=`；**没有**加粗标题行 |
| `\tempo` | 每个谱例块都有 |
| `% GM` | 每个 `\new Staff` 都有，编号与乐器对应 |
| 谱例范围 | 与 `NOTICE.md` 按文章登记表里的范围**不重叠** |
| 编译 | `validate-content.mjs` 通过，`build-notation.mjs` 0 error |
| 移调 | 移调乐器有 `\transposition`，值用 english 音名（`bf` 不是 `bes`） |

可以用脚本一次查完，我写过一个小工具 `check-article.mjs`（在 `materials/tools/`）。

## 8. 我踩过的坑（都是真的）

1. **写手会写空话。** 给它"讲清楚配器风格"，它交回来的每一句都对，但一句都用不上。
   这是本项目的核心风险，不是技术风险。
2. **写手会替你纠错。** 我手工加的一节写"第 2 小节弦乐进来"，实际弦乐到 m.10 才进；
   我任务书里写 `\transposition bes`，在 english 下不是音名。**它反驳你时要采纳。**
3. **静默错误只能靠探针抓。** 有写手漏了 6 个三连音音，小节线整体错位，
   而源文件本身没有小节线检查，LilyPond 会把线挪过去、不报错。只有 `\barNumberCheck` 能抓出来。
   **任务书里必须要求每个谱例都放 `\barNumberCheck`。**
4. **谱例重复会串号。** 谱例按代码哈希查 manifest，同一段出现在两篇会冲突。
   派活前让写手先读已登记范围。
5. **子代理会留下垃圾文件。** 交稿后检查仓库根有没有 `dump.mjs` 这类调试脚本，删掉。

## 9. 这套流程哪里必须改

**上一轮的致命问题不在流程，在输入。**

我给写手的任务书里，资料位置**只有乐谱目录**，没有任何理论资料。结果是：
小节号、音名是真的（对着谱面核过），但"这里有四种推迟手段""动机由五个参数构成"
这类分析框架**全是写手凭自己的知识生成的，没有出处**。

### 必须改的三处

**一，任务书第 ④ 项要加资料路径。**
不要只给乐谱，还要给：对应的教材章节、和声标注文件、分析论文的页码。
例如写"终止式"那篇，任务书里要写：

> 必读：`local/materials/theory/open-music-theory/cadenceTypes.md`（终止式分类）
> 参考：`local/materials/theory/dcml-abc/n04op18-4_01.harmonies.tsv`（该乐章逐拍和声）

**二，任务书要加一条硬约束。**
"文章里的每一个分析性论断，都必须能指到上述资料里的某一页、某一节；指不到就降级为
描述（只写谱面上有什么），或删掉。"

**三，质量门要加一条验收。**
抽查三到五个分析性句子，让写手（或自己）指出去处。指不出来的，退回重写。

### 一句话总结

**配货配的不只是乐谱，还要配理论。** 写手拿不到的东西，等于没有——它会用自己的知识填，
而那些知识没有出处，看起来专业，实际不可追溯。

## 10. 可以直接抄的任务书骨架

```
## 文章
content/<路径>/<slug>.md
方向：<一句话的判断句>

## 必须讲清
1. <具体音乐问题>
2. <具体音乐问题>
3. <具体音乐问题>

## 必读资料（分析性论断必须能指到这些）
- <教材章节路径>
- <和声标注 / 论文页码>

## 拟用谱例
<作品>、<乐章>、<大致小节>

## 源码
<绝对路径>；切片：node qcut.mjs <file> <变量名> <startM> <endM> <每小节拍数>

## 硬规则
- 围栏属性 title="..." location="..."，不要加粗标题行
- \tempo 必填；每个 \new Staff 写 \set Staff.midiInstrument + % GM（编号：钢琴 0、小提琴 40…）
- 移调乐器写 \transposition，值用 english 音名（B♭ 写 bf，不是 bes）
- 每个谱例用 \barNumberCheck 复核小节数
- 1500–3000 汉字，论断落到小节与音名
- 不做音高校验
- 拿不到谱例就写占位，不要停工
- 不要动 NOTICE.md 和 index.md，在回报里给出登记行
```
