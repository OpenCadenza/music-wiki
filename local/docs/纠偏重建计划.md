## 1. 已确定的规则

- 全领域自由选题，取消贝多芬起步重点。
- 顶层使用 techniques、composers、ensembles、styles、notation；技法六维照用户目录。学者自主确定位置，可建子目录，不实施原建议的 forms／genres 顶层轴。
- 初整角色只在预备轮。正式轮资料助手亲自完成新资料取得、初步整理和入库。
- 所有可读资料同等可用，新资料也能启发其他学者选题。
- 资料请求主要用 Codex 原生消息。看板记录学者研究范围；每篇完成归档一条，主控在仓库根目录串行提交content与local全部非忽略改动。
- 原始资料、阅读资料与大型产物继续忽略，不进入主仓库Git历史；入口与catalog轻量索引纳入Git。
- 资料助手确保交付谱例正确、符合要求，找不到就如实报告；学者无需验谱，可使用占位。
- 首批约20篇；每篇成稿归档、提交后，整批结束再由gpt-6.1-terra / medium集中编辑复读。
- 单仓库正式轮允许维护content与local研究区，其余站点工程文件仍不在写作范围。本轮只改local/docs，不启动正式构建。

## 4. 预备整理怎样分工

两个 gpt-6-luna / medium 初整代理分别负责：

1. 教材、HTML／文本、标注数据、来源卡和机器可读谱源入口。
2. PDF／原谱图片的 EverythingMarkdown OCR、页数与本地图像关系、转换索引。

初整只做可发现、可阅读和资料性质区分，不替音乐学者做理论结论，也不逐条事实审计。

预备资料包括26个来源入口、已保存网页和文本、OMT旧版教材、DCML标注、各类编码谱源及原始研究PDF。OMT旧版与OMT2、全文与摘要、标注与原谱、下载成功与实际阅读分别说明。

PDF等非文本文档严格用用户指定 EverythingMarkdown 转Markdown与图片，原件只读。队列当前批准范围为[上传清单](实施记录/2026-10-28-预备轮/OCR待上传清单.md)中的32PDF和9JPG。用户已明确授权传给PaddleOCR，凭据只用于服务认证，不写入产物或Git。

成功转换复用已有结果；已提交任务保存jobId，续跑轮询同一任务；遇到确定网络／配额阻断停止后续提交并保留真实状态。不能把未转换资料标为已读或用其他提取器偷偷替代指定OCR。

大型PDMX等数据包先保留目录，不盲目全量转换。来源失败和未缓存的历史缺口如实保留，有限预备整理不冒称全库都已完整阅读。
