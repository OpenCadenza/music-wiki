# DSH 首批实施计划：音乐学者子代理方案

版本：2026-11-16，DSH 运行时首批。承接[子代理工作流](../../子代理工作流.md)、[写作偏好](../../偏好-知识库写作.md)、[纠偏重建计划](../../纠偏重建计划.md)。

本计划是把原 Codex 方案迁到 DSH 的执行版：规则内核不变，协调机制改用 DSH 原生能力。规则冲突时以本页与用户最新确认优先。

## 1. 目标与边界

目标：启动正式轮第一批，约 20 篇文章，选题完全自由；逐篇完成研究、谱例交接或如实缺谱占位、研究归档、串行版本提交；整批结束后集中编辑复读。

本轮允许维护 `content/` 与 `local/` 研究区。不修改根 README、NOTICE、脚本、站点配置、CI 或其他 `content/` 外站点工程文件。不推送、不发布，不整体合入 main。

不改动其他工作树。本工作树已有独立研究资料副本（见第 3 节），全部读写在本工作树内完成。

## 5. Team 任务板规范（替代原公共看板）

任务板承载"谁在做什么、卡在哪、谁在等谁"这类连续变化的状态。每位学者了解全局靠 `team_task_list`，不再维护手工在研目录。

### 5.1 任务类型与命名

| 前缀 | 用途 | 创建者 | owner |
| --- | --- | --- | --- |
| `S<n>` | 学者在研选题 | 学者本人 | 该学者 |
| `R<n>` | 资料请求（学者发起） | 学者本人 | 资料助手 |
| `D<n>` | 资料交付（助手回执） | 资料助手 | 资料助手，完成后关闭 |
| `A<n>` | 成稿归档（一篇一篇） | 学者本人 | 该学者 |
| `C<n>` | 主控串行提交 | 主控 | 主控 |
| `E1` | 整批编辑复读 | 主控 | 复读代理 |

主题写法：`S1 研究：<选题短语>`、`R3 资料请求：<需要什么>（S1）`。主题只写动作与对象，不带序号以外的状态词。

### 5.2 描述必填内容

选题任务（`S`）描述至少写明：研究的中心问题、已读与拟读资料范围及实际进度、拟用作品或案例、正文拟放位置（目录与文件名）、当前缺口、与其他选题的重叠或关联。

资料请求（`R`）描述写明：研究问题与用途、需要的文献或作品定位、可接受的形态（全文／页段／谱源／编码／图像）、为什么现有资料不够。

### 5.3 写作用域

`write_scopes` 用工作区相对前缀，声明本任务预计改动的路径：

- 学者：`content/<自己选定的目录>/`、`local/docs/研究归档/`
- 助手：`local/resources/`、`local/origin_resources/`、`local/workbench/`
- 主控：`local/docs/`、`content/` 整合处

作用域只是提示，不构成锁；真正避免冲突靠第 7 节的路径分配与第 9 节的串行提交。

### 5.4 状态流转与写权限（2026-11-16 探测实测）

`pending`（已提出）→ `in_progress`（认领）→ `completed`（交付或成稿）。完成后关闭。阻塞关系用 `blocked_by`：`R` 任务声明 `blocked_by` 对应 `S` 任务，`A` 任务声明所依赖的 `R`／`D` 任务。

**实测权限边界**：子代理可以 `team_task_create`／`team_task_list`，但 `team_task_update`（认领、改期、关闭）被子代理侧的审查策略拒绝（`Auto review rejected`）。因此本轮实行**单写者模型**：

- 子代理：只建卡。选题、资料请求、成稿各建一张，描述写全；不尝试 `team_task_update`，也不为重试该工具消耗时间。
- 主控：唯一的认领、指派、完成、删除者。收到子代理回报后把对应卡片置为 `in_progress`／`completed`，需要时把 `owner` 指派给该子代理。
- 结果：任务板仍是全局唯一在研视图，且不会因为权限拒绝而卡住子代理。

任务板不负责唤醒：跨代理的催办与交付用 `send_message`，任务板只留证据。

## 6. 研究归档 Markdown（保留）

每篇成稿一条记录，路径 `local/docs/研究归档/<文章slug>.md`，由该学者写、只写自己的。必填：学者、最终选题与中心论证、实际采用的资料范围（含实际读到的页段／章节）、正文位置、谱例（助手交付片段或真实定位占位及缺口）、未解决的缺口、状态（`已成稿，待本批复读`／`已复读`）。

这是研究过程的正式存档，进入 Git。格式从简，不写成文章模板，不复制正文。归档与任务板的分工：任务板随做完就关，归档长期保留研究依据。

## 7. 路径分工（避免互相覆盖）

| 区域 | 写入者 | 规则 |
| --- | --- | --- |
| `content/**` | 各学者 | 按选题分目录，不同学者不写同一文件；跨文共享谱例由主控整合 |
| `local/resources/**` | 仅资料助手 | 学者只读；助手按第 6 节协议入库并更新入口 |
| `local/origin_resources/**` | 仅资料助手 | 原件只读保存，不覆盖已取得原件 |
| `local/workbench/research/**` | 各学者 | 每人在 `research/<学者名>/` 下写研究笔记 |
| `local/docs/研究归档/**` | 各学者 | 一篇一条，只写自己的记录 |
| `local/docs/实施记录/**`、`local/docs/*.md` | 主控 | 学者不写规则文档 |
| `content/` 共享谱例、目录导论整合 | 主控 | 学者可提议，不直接改别人的文件 |

同一段谱例全库只保留一份，其他文章链接到它的稳定位置。

## 8. 通信协议

- 学者 → 助手：先建 `R` 任务（写清第 5.2 节内容），再 `send_message` 给助手，消息里给出问题、需要的定位和任务编号。不贴整本资料。
- 助手 → 学者：`send_message` 回执，同时完成 `R`、建 `D` 或直接复用 `R` 写入交付说明。回执必须区分：拿到了什么、是否全文、实际页段、原件与阅读副本路径、还缺什么；交付谱例时说明作品／乐章／小节与已完成的核对。
- 学者 ↔ 学者：可直接 `send_message`，用于相近选题沟通、共享资料、避免重复劳动。
- 学者 → 主控：成稿后申请提交（`A` 任务 + 消息），不自行 `git add`／`commit`。
- 主控 → 学者：派活、催办、整合通知、复读意见下发。
- 代理结束回合后由主控用 `send_message` 重新激活，或另起新代理并给出准确续接位置。不重复派活。

## 9. 版本提交

主控在当前仓库根目录串行执行 `git add -A -- content local` 与 `git commit`，一次提交形成"该篇完成时"的快照。提交说明标明完成的文章与研究归档记录位置。

- 多个代理不得并发操作 Git index；学者与助手不执行 `git add`／`commit`。
- 原始资料、阅读正文与大型产物继续由忽略规则排除；文档、研究笔记、归档、工具、入口与 catalog 索引进入历史。
- 提交可以包含其他学者此时已落盘的进行中改动，不为"整理提交"覆盖或丢弃它们。
- 不推送，不发布，不整体合入 main。

## 10. 谱例与工程要求（复核）

LilyPond 目标 2.26.0，统一 english 音名，代码块自包含可编译。谱例围栏带 `title`（作品名、作品号、乐章）与 `location`（小节范围），需要时用稳定 `id`。提供正确速度信息，为试听补的数值标为播放设置。每个声部指定乐器与 0–127 的 GM 编号。移调、调号、拍号、弱起、力度等必要上下文保留。

谱例正确性与符合要求由资料助手负责；学者不验谱。找不到满足要求的谱例，助手如实报告"没找到／定位不明／编码未完成／正确性无法确认"，学者用真实定位占位，未知位置写"待定位"，不编造小节号。编译通过只说明工程可用，不替代音乐内容核对。

本机工具链现状（M0 已核对）：

- LilyPond 已装 2.26.0，位置 `E:\GreenSoftware\lilypond-2.26.0\bin\lilypond.exe`，不在 PATH 上。需要编译检查时用完整路径调用，或设 `LILYPOND_PATH`（`scripts/build-notation.mjs` 依此变量与 `.tools/lilypond-2.26.0/`、PATH 三级查找）。
- `abc2midi`、`fluidsynth`、`ffmpeg` 未确认可用；只做谱例可编译性检查时用 LilyPond 即可，播放／音频产物不是本轮必需。
- Python 3.14（`C:\Python314\python.exe`）、Node 可用。
- 站点工程脚本（`build`／`smoke-site`）本轮不运行：旧 smoke 检查硬编码贝多芬页面，与首批自由选题不符，问题记入 `local/` 而不改脚本。

## 13. 验收与失败处理

验收看的是：文章确实从实际阅读中生长出来、有实质理解与论证、谱例真实且由助手负责正确性、每篇有归档记录与版本快照、状态不虚报。

失败处理：

- 模型或工具不可用：先降级路径（副模型、串行执行），并如实记录，不伪装成正常运行。
- 代理中断：先查 `list_agents`、任务板与实际落盘进度，能续就续，不能续就新代理并给出准确续接位置。
- 资料缺口阻断论点：缩小论点、补资料或留研究稿，不用模型记忆补出正文，不写免责声明掩盖缺口。
- 谱例找不到：如实报告 + 真实定位占位，不放弃选题。
- 提交冲突：串行化，失败保留工作树与归档，修复后重新提交，不冒称已形成版本。

不把"已取得／已读／已写／已编译／已提交／已发布"混为一件事。
