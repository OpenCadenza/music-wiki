## 三、必须人工决定 vs 可脚本化

**必须人工决定（脚本不该替你拍板）**

1. **正文是否面向创作 Agent 说话**（P1-7）：决定首批 16 篇是否改写；直接改文与删除“检查清单”段落属内容修改。
2. **许可登记的唯一载体与取值**（P1-1）：NOTICE 汇总还是 provenance 分篇；是否允许“待确认”长期存在、谁负责确认版权。
3. **术语正名表**（P1-6）：`乐思/乐念`、`挂留/悬置`、`模进/序列`、`Prinner/普林纳` 各选一个，选中后才有脚本可执行。
4. **侧边栏权威顺序与 `piano-sonatas` 目录名**（P2-1/P0-3）：改 `config.mts`/`smoke-site.mjs`/目录名都在“不改脚本配置”红线内，需用户授权。
5. **同段多篇的归属与分工**（P1-5）：哪一篇“拥有”某段谱例、另几篇如何改写措辞，属作者判断。
6. **README 目录结构是否回写为平铺**（P2-2）。

**可脚本化（第四轮可直接做，不需逐篇人工）**

1. 复跑 `validate-content.mjs` 作门禁基线；补一条“每篇是否被本目录 index 收录”检查（P0-2 的机器版）。
2. 生成“作品 × 小节 × 文章 × 是否已链接”矩阵与零入链/零出链清单（P0-2、P1-5 的输入）。
3. 幻影谱例 id 对账脚本：provenance 谱例表 id ↔ 47 个真实围栏 id ↔ `score-board`（含“占位/关联引用”识别）（P1-2）。
4. 占位一致性检查：统一正则，列出 4 种写法的位置，输出可批量替换清单（P1-4）。
5. `manual:gaps` 与围栏/幻影 id 对账，自动标出“已回填仍在缺口表”的过期行（P1-4）。
6. 归档头部 schema 校验 + 批量补空字段（只补字段，不改结论）（P1-3）。
7. 术语一致性词表检查（按选定的正名/别名表输出违规位置）（P1-6）。
8. 首页与各 index 的“篇数/收录数”从 `content/` 自动统计（P0-1，避免再次过期）。
9. `smoke-site.mjs` 路径从 `content/` 自动推导（需授权改脚本）（P0-3）。
