# 续作说明（2026-11-20，三名学者共用）

> 先读 `用户要求总账.md`（用户本轮全部要求与落点）与 `local/docs/研究归档/_运行记录/` 里你前任的记录。

这一轮不重新选题，是把 20 篇既有文章收尾。所有要求都是**偏好与事实**，不是硬性规定；怎么做由作者判断。

## 站点事实（供你决定写什么、怎么写）

- 页面支持：Mermaid 图、数学公式（`$…$` 与块级）、表格、代码块、提示容器（`::: tip/info/warning/danger/details`）、code-group、折叠块 `<details>`。
- 标题：第一行短标题（2–8 字），下一行一行副标题段落 `<p class="doc-subtitle">长问题</p>`；frontmatter 写 `title: <短标题>`，侧栏只显示它。语言不限。
- 正文可以自由引用外部资料、点名作者、指出出处；书目与许可登记在 `provenance/<与 content 相同的路径>.md`（已建好骨架），不把整份参考文献表搬进正文。
- 需要谱例时用普通文本写清作品、乐章、小节范围即可（不要写成 `lilypond` 围栏）；谱例由助手回填，你不需要管 id 或链接。
- 谱例到位后读一遍，自行决定文章要不要改。

## 每篇的收尾动作（按你认为合适的顺序）

1. 标题改成「短标题 + 副标题」，补 frontmatter `title`。
2. 把用到的资料登记进 `provenance/<path>.md`；如果文章有「参考文献/资料索引」章节，内容搬进该文件，正文那节可以删掉（也可以保留，你自己判断）。
3. 看看正文里的 ASCII 图：如果换成 Mermaid、表格或公式更清楚，就换；不想换也可以。
4. 读一遍已入文的谱例，按需要修文章。
5. 更新 `local/docs/研究归档/<slug>.md`，写清这轮改了什么、依据、未决。

## 边界

- 只改自己署名的文章与对应 provenance 文件；不改别人的文章、不改 `index.md`、不改脚本与站点配置、不执行 git。
- 写完一篇（或一批）给 lead 发消息：改了哪些文件、标题新写法、provenance 填了什么、还有什么没定。
