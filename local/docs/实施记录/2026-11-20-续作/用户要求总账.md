### 2026-11-20 新会话实测（与交接假设不符，已记入上表 #18）

`list_subagent_models` 与 `subagent` 的实测结果：本会话唯一被授权的子代理路由是
`magpie / auto/deepseek-v4.1-flash`；`magpie / group/gemini-3.8-flash` 报
`child LLM route ... is not allowed for this Session`，`auto/gemini-3.8-flash` 报
`pi-ai provider "magpie" has no configured model`。

- 模型本身是配好的（`~/.dsh/settings.yaml` 与 `profiles/web/cordis.patch.yml` 的 magpie 段都有 `group/gemini-3.8-flash`）。
- 拦截点在 profile 的 `subagent-model-selection-settings.allowedModels`：里面只有 `tbtb/deepseek-v4.1-flash`、`tbtb/glm-5.3-flash`，而 `tbtb` 提供方在当前 `settings.yaml` 里已不存在，于是实际可用集合退化成"会话默认模型"这一个。
- 结论：**"换新会话就能用 gemini"不成立**；要让学者用 gemini，必须先改这条白名单（profile 配置，需重启 DSH 生效）。
