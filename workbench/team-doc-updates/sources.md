# 资料来源、原件与阅读库

资料包括教材、研究论文、作品与作曲家介绍、版本导言、乐器与演奏资料、原谱、编码和分析标注。选题需要什么资料，就寻找什么资料；不能只按能否取得 LilyPond 源码选择主题。

## 两层资料库

原始资料在 `origin_resources/` 保存取得时的文件和来源关系。可阅读、可查找的 Markdown、图像、标注和按需加工谱源放在 `resources/`，共同索引指向真实原件。

预备轮由初整角色处理已有材料。正式轮资料助手自己完成新资料的取得和初整，不再向初整角色派单。新旧批次的可读资料具有同等价值，所有学者都可由新增材料发现选题。

来源卡说明题名、作者、类型、版本、原件、可读副本、真实范围和缺口。它是入口，不能代替学者阅读正文。

## 已有来源类型

实际文件与取得状态以来源目录和资料索引为准，下面只说明用途，不保证每个来源已取得全部内容。

| 类型 | 已有来源线索 | 应注意的范围 |
| --- | --- | --- |
| 理论与训练 | Open Music Theory、MIT OCW、Belkin、partimenti | 已取得 OMT 旧版不等于 OMT2；作业、教材和规则文献性质不同 |
| 分析与音乐学研究 | Music Theory Online、大学机构库、贝多芬分析资料 | 区分论文全文、样章、摘要、课程导读和仅目录页 |
| 作曲家／作品与版本 | 出版社导言、作品研究、Beethoven-Haus、Bach Digital、Chopin Online | 目录条目、有限选页和完整作品不可混称 |
| 乐器与演奏 | Philharmonia 等资料 | 文字、图像和视频入口分别登记，不虚报未取得内容 |
| 标注与机器可读谱源 | DCML、Humdrum／Kern、Mutopia、OpenScore、ABC 合集 | 标注是分析资料；编码、原谱和排版副本要区分 |
| 大型数据集 | PDMX 等已取得归档 | 先列内容与版本，不把历史数据包称最新全量谱库 |

原资料库已有 Beethoven 奏鸣曲／四重奏 Kern ZIP 的取得记录。因此“Mutopia 没有某个 .ly”只说明该渠道没有现成源码，不能说作品无谱源。

旧 Agent 笔记、自编模型、旧知识文章、日志、失败页面和空文件保留以便追溯，但不进入默认学术资料入口，也不循环引用为新文章的依据。

## 取得与初步整理

先查已有库和引用链，再找相关作者、机构、期刊或谱源的正文。保留原文件，转换产生新副本。

PDF、图像和其他非文本文档用已选定的 EverythingMarkdown 转 Markdown 与图片。明确页码与分段，保留图表；谱面 OCR 不等于可用的音符编码。

网页保留有效正文和图表关系；压缩包按需解出文献、标注或谱源。大型包不全面转码，短 include 壳文件不因小于某个字节数就判坏。

状态要分清：已发现、已取得、可读、仅摘要、失败、已被学者选读、实际采用。助手返回路径、页段与缺口，不能用搜索结果代替全文。

## 谱源的实际用途

Mutopia 的原生 LilyPond 便于加工；OpenScore／MusicXML、Humdrum／Kern、ABC、扫描谱和原稿图像也可按需要使用。某次转换失败只登记具体输入、工具和错误，不宣布整个格式永久不可用。

乐谱代码暂缺时保留真实定位的占位并继续寻找，不由可下载性替文章选例。不要因为许可不开放或未明确而放弃研究问题；按项目要求保留来源和许可信息，未知状态如实记，不改写为已确认自由授权。

## 登记在正文之外

NOTICE 记录正式采用的文献与谱例来源、版本、渠道、许可及文章对应关系。详细下载、阅读和转换过程保存在本地。

正文不堆来源表、许可和防御性声明。文章涉及资料分歧时自然解释音乐问题，不把过程登记当成内容。编译通过不替代阅读、音乐判断或来源权利声明。
