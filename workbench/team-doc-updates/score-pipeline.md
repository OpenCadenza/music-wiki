# 谱例取得与加工

谱例工程服务于研究和解释。作者提出需要的作品与片段，助手取得和处理，学者阅读并完成分析；不要先把全曲配货完，才允许开始研究。

## 原件和副本

原始编码、扫描谱或原稿图像保存在原始库。转换、迁移和切片都写新副本，保留原文件与来源关系。

下载后检查文件确有内容、格式符合预期、依赖没有缺失。0 字节或错误网页需要修复；不能按“低于 500 字节”一律判坏，合法 include 壳可能很短。

原件和阅读记录是需要保留的资产，不应被当成随时可丢的缓存。

## 先取得有意义的材料

可使用 LilyPond、MusicXML、Kern、ABC 或扫描谱。PDF／图像按选定工具 OCR 成可阅读 Markdown 与图片，谱面仍需图像或可靠编码；OCR 文本不能直接冒充音符转写。

没有现成代码不等于没有原谱。转换某份失败时记具体输入与错误，按需处理目标片段或保留占位，不宣告整个来源格式不可用。

## LilyPond 工作副本

已有可用工具可在本地资料工具目录复用，例如音名转换和按小节切片工具。路径按各工作区实际位置确定，不把某台机器的绝对路径当团队通用命令。

必要步骤：

1. 查看原语言、版本、include 依赖和乐章／编制。
2. 用目标工具的 convert-ly 迁移到 2.26.0，不能只改版本字符串。
3. 原本为 english 的源不重复套其他语言映射；音名转换读取该语言定义，跳过字符串和注释。
4. 按所需片段切出相关声部，保留弱起、拍号、调号、速度、力度和移调等上下文。
5. 组装自包含代码块，编译并处理与该片段有关的明确错误。

编译检查退出码、有效乐谱与输出，不只搜索一行 error。复杂输入偶发崩溃时有限重试并保留日志，不为排错擅自改变音乐内容。

不进行每个谱例的全面逐音、MIDI 比对。分析所需的读谱仍由作者进行；已知转换错误或定位疑点可定点检查，不能把反复校谱当成生产主线。

## 嵌入格式

代码声明目标版本与音名：

~~~~lilypond
\version "2.26.0"
\language "english"
~~~~

围栏属性提供 `title="作曲家 作品名称 作品号 乐章"` 与 `location="mm.起–止"`；需要跨文章引用时用稳定 id。每段只出现一次，其他文章链接到它。

每个声部写合法的 midiInstrument 和明确 GM 注释。当前构建使用 **0–127**，示例为：

~~~~lilypond
\new Staff {
  \set Staff.midiInstrument = "violin"
  % GM 40
  ...
}
~~~~

不要混用 1–128 的编号表。移调乐器按 english 音名给出必要 transposition，音色、移调和编制必须与所用片段对应。

速度保留来源信息。为了试听补选数值时，在生产记录说明它是播放设置，不能冒称作曲家标记。

## 长度、缺口与交付

谱例长度由解释需要决定，应足以展示上下文，不固定小节配额。不复制整乐章充当短例。

代码暂缺可写作品名称、作品号、乐章和真实位置占位；位置未明就记待定位。中心知识未完成研究时保存研究稿，不能用占位掩盖。

交付包含原件位置、加工副本、作品与片段、采用来源、转换情况、必要播放设置和已知缺口。主控统一更新 NOTICE 与共享片段登记。编译成功只说明工程可用，不为音乐正确性作整批背书。
