# 纠偏与重建计划

设计日期：2026-10-28。本轮完成要求整理和方案设计；**没有迁移原始资料、归档 content、重写知识文章或发布新库**。

用户要求见[写作偏好](偏好-知识库写作.md)，生产机制见[新子代理工作流](子代理工作流.md)。这里说明旧工作的哪些问题要改、怎样保住资产并从头重建。

## 1. 这次要修复什么

根本问题是知识生产没有建立“阅读资料—理解—著述”的过程。旧流程先由主控根据可用谱源定题、预设要点，再让写手围绕乐谱交稿；理论、作品研究、作曲家与背景资料没有成为实际写作输入。

因此问题同时存在于输入、选题方式和生产流程。不能只给旧任务书补一栏“参考文献”，便继续原来的填空生产线。

另一种错误也要避免：为纠偏而要求每个分析句在文献里找到原话、禁止自己的分类和解释。这会把文章重新变成资料转述。新流程要求有真实阅读和可说明的推理，同时保留独立分析。

旧文没有显示来源名称，本身不足以证明作者没读过资料，因为此前规则就要求正文不写来源。本次纠偏依据包括用户指出的问题、旧派活流程及旧 Agent 交接中的自述。归档全部旧文是本轮明确要求，不需要先花时间逐篇裁定每句话是真是假。

## 5. 可执行的恢复顺序

### P0：校准规则与保留原状

本轮已完成要求整理、只读盘点、新方案和旧本地文档备份。

正式实施开始时，保存两个项目的实际状态、未提交变更和旧内容清单。无需为了备份覆盖用户改动，也不重写 Git 历史。团队的旧“完整”“质量基线”声明先撤销，避免其他成员继续按错规则扩写。

### P1：迁入原始资料，切换唯一工作入口

将用户笔误“易懂到”按“移动到／迁入”理解。目标路径为 `local/origin_resources/`，直接保留原 music-library 内部层级。

采用“复制到目标 → 一次文件完整性核对 → 切换路径 → 旧入口退役”的可恢复迁移，而非先删源。目标存在同名文件时先比较，不能盲目覆盖。

完整性核对只核文件数量、相对路径、大小和一次摘要，不做全库音乐事实审计。迁入完成后核对本地脚本与文档仍引用的旧绝对路径，保存旧新路径映射。原件中的历史文字不批量改写；现行入口和脚本改用新路径。

迁移目标是由新原始库接管，不长期维护两个活跃资料中心。旧副本的清理放在迁移和引用切换完成后，不与首次复制混在一起。

**完成标志**：原始库完整可用，历史失败记录也保留；接手者能从新位置找到已有资料，不再靠旧程序目录工作。

### P2：先做能支持试写的资料入口

由资料初整代理 gpt-6-luna / medium 整理第一批，再持续处理其他资料：

- 给教材、论文／作品研究、版本与背景资料、原谱／编码建立可找的入口。
- 优先利用现有 OMT、DCML 等阅读副本，核对对应原件，注明版本和范围。OMT 旧版不能改名成已取得 OMT2；DCML 标注不能当作唯一无争议分析。
- 按需抽取 PDF／HTML、解开相关谱包；页码和原文件关系要能找回。扫描谱保留图像入口。
- 空文件、错误页面、仅目录／摘要、下载失败分别标记；不把“有一个 URL”计为资料已读。
- 大数据包和重复渲染物不全面转换。旧 Agent 内容不混进可信正文语料。

**完成标志**：学者能从索引打开真实材料，读到足以开展研究的连续内容；不要求全库都处理完。

### P3：修正共同文档，关掉旧生产入口

按第 3 节逐份改写团队文档及仓库根规范。全局设计、写作方法、源库说明和工程处理分开说明；当前进度不继续夹带失效的生产指令。

团队文档写可供所有成员使用的方法。本地盘符、个人偏好、详细贝多芬研究笔记放 local；团队文档不能把本机绝对路径当成全员可用链接。

**完成标志**：沿任一现行入口进入，都不会再读到“只给谱源派写手”“禁探索”“每句必须指页”“所有旧谱例正确”等规则。

### P4：归档所有旧内容，从新稿开始

归档整棵旧 `content/`，包括 37 篇文章、11 篇导论及相关文件；同时保存对应 NOTICE、内容清单、状态和摘要。归档放 `local/archive/<批次>/`，不在公开正文里加一个历史目录。

全部旧文退出新库的知识依据。可以从旧文章发现待研究问题，但新稿必须重新阅读资料、独立组织论证，不做换词或补几条引文的翻修。

旧谱例和工具可按需采用。采用时保留来源关系、检查必要上下文与可编译性，遇到已知问题再处理；不为复用做全面逐音校验，也不给 51 个块整体准确性背书。新 NOTICE 按实际采用材料登记，旧 NOTICE 随归档保存。

正式库切换在新入口和首批文章准备好后进行。不要在迁移中间发布一个空目录，也不要把旧页面、旧构建物或旧检索镜像误标成新库。新内容同步与旧镜像撤换应使用既有发布流程另行完成。

**完成标志**：旧内容可恢复、可追查，但没有混入新正式正文或新检索语料；所有新文章均从重新研究开始。

### P5：小批验证新的生产机制

先开一名音乐学者 gpt-6.1-terra / high 与一名资料助手 gpt-6-luna / medium。初整可利用剩余并发位置持续工作。

让学者从已可读资料中自由发现选题，试写一小批文章。起步仍照顾贝多芬奏鸣曲的既定重点，但不按旧 17 篇标题逐一返工，也不按现成 .ly 文件排选题。

主控或独立编辑复读中心解释，并查看实际阅读记录。需要补关键材料就补，能独立推导的分析保留，不用逐句找“同款结论”。

**完成标志**：文章有真实知识输入，能看出理解与重新组织；助手确实让研究更顺畅，缺谱与缺研究的处理分清。

### P6：检验读者收益，再分阶段扩展

让 Agent 实际用新库辅助创作，记录检索文章、获得的音乐认识、采用方式和仍缺的知识。谱例编译、站点浏览和检索范围也按既有工具验证一次。

若文章读起来仍像术语堆、资料摘要或未经研究的顺口解释，先改生产方法，再扩大并发。

之后按知识缺口逐渐完成贝多芬钢琴奏鸣曲、其他钢琴作品、室内乐、四重奏、管弦与协奏曲、声乐等领域，并发展通用知识及其他作曲家。阶段优先级由有价值的问题与资料成熟度共同决定，不能由 Mutopia 是否有源单独决定。

**完成标志**：每阶段报告真实覆盖与缺口；不以“每个目录有几篇”宣布完整音乐知识库已经完成。

## 6. 整体架构建议

多维入口仍然有价值。文章数量不均不是取消某个知识维度的理由；避免重复靠内容归属和链接，而不是把所有东西都塞到两个目录。

建议保留以下学科入口，先在团队 README 说明全貌，有内容时再建目录：

| 入口 | 主要内容 |
| --- | --- |
| `techniques/` | 动机、旋律、和声、对位、节奏、织体、配器等原理与写法 |
| `forms/` | 乐句、段落、奏鸣曲式、回旋、变奏等组织逻辑 |
| `genres/` | 奏鸣曲、交响曲、协奏曲、歌曲等体裁的惯例、演变和创作问题 |
| `composers/` | 作曲家、作品与风格的具体研究，按需要分体裁 |
| `ensembles/` | 乐器与编制、演奏条件、音色与平衡 |
| `styles/` | 时期、流派和风格语境，包括爵士、流行及其他传统 |
| `notation/` | 记谱、移调、LilyPond 等对创作有用的实现知识 |

这是本轮建议，不是宣称用户已经定下七个目录。体裁与曲式分别说明；规模小时可以通过导论和链接关联，避免为了分类制造许多空页。

贝多芬仍可沿 `composers/beethoven/piano/sonatas/` 起步，并按需要拓展 variations、quartets、chamber、symphonies、concertos、songs、choral 等。作曲家和体裁导论也要从资料形成，不能用旧导论填空。

同一文章只有一个主要位置，其他语境用链接指向。归属看它主要解释什么，不强制一有跨轴关系就拆两篇。通用原理与具体个案可以各写文章，但应有不同的问题和内容；同一段谱例共享。
