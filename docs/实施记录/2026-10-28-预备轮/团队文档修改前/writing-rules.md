# 选题与写作方法

> 核验日期：2026-10-27
> 硬性格式要求以工程仓库根 `README.md` 为准：
> <https://github.com/OpenCadenza/music-wiki/blob/main/README.md>
> 本文讲的是**怎么写出值得读的一篇**，不是合规检查表（那是
> [`../music-wiki-页面部署/content-rules.md`](../music-wiki-页面部署/content-rules.md)）。

## 一句话原则

**一篇回答一个创作问题，每个论断落到具体小节，用真实乐谱证明。**

反面教材（本项目早期真实发生过）：整篇在讲"来源可信度、证据边界、这不是贝多芬原作"，
第一条可执行指令出现在全文 87% 处，谱例全部是"声明不是贝多芬"的原创模型。
那样的文档学术上无懈可击，对写谱的人毫无用处。

## 选题怎么定

一个合格的选题必须同时满足：

1. **是一个动作，不是一个话题。** "贝多芬的晚期风格"不是选题；"晚期织体里中音区为什么必须空着"是。
2. **能用 2–3 部作品的片段证明。** 只有一部作品，容易写成作品分析；跨作品才说明是可迁移的写法。
3. **读者读完能动手。** 读完知道自己谱子上哪几个音要改。

选题来源：现有文章里没讲透的问题、写手遇到的真实困难、agent 作曲时卡住的地方。
**不要按作品列表逐个填空**——那是编年史，不是知识库。

## 一篇文章的骨架

不是模板，是信息要求。四项缺一项，这篇就不完整：

| 项 | 要求 |
| --- | --- |
| 论点 | 开头三四句说清"什么时候用这个做法、它解决什么" |
| 机制 | 哪几个音、哪个拍位、哪条声部在做功；参数是多少 |
| 谱例 | 8–20 小节真实乐谱，能完整呈现一个乐思 |
| 可迁移写法 | 读者照着改的规则；可以是叙述，不必编号 |

长度 1500–3000 汉字。超过 3000 说明混进了第二个问题，拆开。

## 论断要落到小节

这是"能执行"和"不能执行"的分界线：

| 不可执行 | 可执行 |
| --- | --- |
| 贝多芬常用低音支撑 | 第 5 小节左手停在 G2 上两拍，右手才进来 |
| 注意音区对比 | 左手固定 C2–F2 写八度，右手不低于 c″ |
| 副部更抒情 | 副部主题落在 g′，比主部低六度，句尾往下走 |

写的时候用"第 N 小节 + 音名 + 拍位"三件套自检。三个都给不出来的句子，删掉。

## 谱例格式

围栏 `title`/`location`、`\tempo`、每个声部的 `% GM` 编号三项必填，硬性规则与判定标准写在
[内容规范](../music-wiki-页面部署/content-rules.md)，这里不重复。写作者只需记住：
**缺标题播放器没有名字，缺速度会以 60 bpm 播放，缺 GM 编号会退回钢琴音色。**

## 不重复，用链接

同一段乐谱全库只能出现一次，放在最详细讨论它的那篇。别处引用写链接：

```markdown
Op.2 No.1 这一段逐音的谱面见`motive-tasks.md`
里的谱例（弱起 + mm.1–14）。
```

构建的 `validate` 会把完全重复的代码块判为错误；这不只是规矩，也是技术约束
（谱例按代码哈希查 manifest，重复会串号）。

## 拿不到谱例时

**写占位，不要放弃选题，也不要自己编一段"贝多芬风格"。**

```markdown
**贝多芬 Op.110 第三乐章，mm.1–20**

> 谱例待补：Op.110 第三乐章 mm.1–20。
```

占位保留作品、作品号、乐章、小节范围；正文照常写分析。后续补谱不必重写文章。

## 派活给写手怎么写任务书

这是本项目跑通三轮的实际做法。任务书必须包含六项，否则写手会用"看起来专业但不可执行"
的方式交稿：

1. **题目与 H1**：直接给出标题，或给出判断句让写手定。
2. **必须讲清的三到五个点**：不要写"讲清楚 XX 风格"，要写"三种做法各自适合什么段落；
   大提琴一唱中音区就空怎么处理"。
3. **拟用谱例**：作品、乐章、大致小节。允许写手调整范围，但要求 8–20 小节。
4. **可用源码位置**：告诉它 `-en.ly` 在哪、怎么定位小节、怎么编译。
5. **占位许可**：明确写"拿不到就用占位，不要停工"。
6. **格式三件套**：围栏 `title`/`location`、`\tempo`、`% GM`。

再加一条纪律：**不做音高校验**。第一轮在 MIDI 比对上花的时间超过写作本身，收益不成正比。

## 人工复核

构建只保证编译通过。合入前必须人看的清单在[内容规范的「合并前人工复核」](../music-wiki-页面部署/content-rules.md)。
写作侧额外自查一条：**小节号是否与通行版一致**——`\cadenzaOn` 段落（如 Op.111 的 Maestoso）
LilyPond 的小节计数与通行版不符，这类段落不要写"第 X 小节"。

## 当前写作水平基线

第一轮五篇（`opening-gestures`、`motive-tasks`、`transition`、`secondary-theme`、
`exposition-closure`）是公认的质量基线：每篇 1500–2600 汉字，谱例全部真实，
论断逐小节落地，正文零来源与免责。后续批次按这个标准对齐。
